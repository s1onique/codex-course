# Windows PowerShell: что это, откуда взялось и как им пользоваться

- **Материал:** к [уроку 0](../../LESSON-00.md) курса «Вайбкодинг с Codex».
- **Уровень:** с нуля; **время:** 20–30 минут.
- **Среда:** Windows 10, встроенный Windows PowerShell 5.1; ничего устанавливать не нужно.

## 1. Зачем нужна командная строка?

Обычно мы открываем папки мышью и выбираем действия в меню. В командной строке можно попросить компьютер сделать то же самое текстом:

```powershell
Get-ChildItem
```

Эта команда показывает содержимое текущей папки.

**PowerShell совмещает три роли:**

- **Командная оболочка (shell)** — принимает команды и запускает программы.
- **Язык программирования** — позволяет использовать переменные, условия и циклы.
- **Среда автоматизации** — помогает выполнять повторяющиеся действия с файлами, процессами, службами и другими ресурсами.

В нашем курсе PowerShell нужен прежде всего для работы с **папками проектов, Git и инструментами разработки**.

### Терминал и PowerShell — не одно и то же

**Терминал** — окно, в котором мы вводим команды и видим результат. **Оболочка** — программа, которая понимает команды. Например, приложение Windows Terminal может открыть вкладку с PowerShell, Command Prompt или другой оболочкой. Обычное окно Windows PowerShell нам тоже подходит.

**Сценарий (script)** — файл, в котором записано несколько команд. Файлы сценариев PowerShell обычно имеют расширение `.ps1`.

## 2. Краткая история

В старых версиях Windows широко использовалась оболочка **Command Prompt** (`cmd.exe`) и пакетные файлы `.bat`. Они подходят для простых задач, но автоматизировать сложное управление системой с их помощью неудобно.

В начале 2000-х Microsoft начала работу над проектом **Monad**, связанным с инженером Джеффри Сновером (Jeffrey Snover). Важная идея заключалась в том, чтобы передавать между командами не просто текст, а **объекты** — данные с именованными свойствами.

| Дата | Событие |
| --- | --- |
| 2002 | Идеи Monad сформулированы в *Monad Manifesto*. |
| **2006-11-14** | Официальный выпуск **Windows PowerShell 1.0**. |
| 2009–2013 | Выпуски версий 2.0, 3.0 и 4.0. |
| **2016** | Выход **Windows PowerShell 5.1**, знакомого пользователям Windows 10. |
| **2018** | Выход открытого кроссплатформенного **PowerShell 6** на .NET Core. |
| Позже | Развитие современной ветки **PowerShell 7.x**. |

### Windows PowerShell 5.1 и PowerShell 7.x

Важно: это **два разных продукта**, а не просто два оформления одной программы.

| | Windows PowerShell 5.1 | PowerShell 7.x |
| --- | --- | --- |
| Где работает | Windows | Windows, Linux, macOS |
| Технологическая основа | .NET Framework | Современный .NET |
| Имя программы | `powershell.exe` | `pwsh.exe` (Windows) |
| На Windows 10 | Уже установлен | Устанавливается отдельно |
| Для первого урока | **Достаточно** | Не нужен |

PowerShell 7 устанавливается **рядом** с Windows PowerShell 5.1 и не заменяет его. Примеры ниже рассчитаны на **5.1**. Не всё из интернет-инструкций для PowerShell 7 работает в 5.1: например, операторы `&&` и `||` в Windows PowerShell 5.1 отсутствуют.

## 3. Открываем PowerShell

1. Откройте меню **Пуск**.
2. Наберите **Windows PowerShell**.
3. Запустите обычное приложение, **не** «Запуск от имени администратора».

Вы увидите приглашение примерно такого вида:

```text
PS C:\Users\Anna>
```

Оно означает: «PowerShell готов к новой команде; сейчас рабочая папка — `C:\Users\Anna`». **Не набирайте** `PS C:\Users\Anna>` — это приглашение, а не часть команды.

Проверьте версию:

```powershell
$PSVersionTable.PSVersion
```

В обычном Windows PowerShell на Windows 10 основная версия — **5.1**.

**Полезные клавиши:** `Enter` — выполнить команду; `Tab` — дополнить имя или путь; стрелка вверх — предыдущая команда; `Ctrl+C` — остановить выполняющуюся команду (**не** скопировать текст); `exit` — закрыть сеанс.

## 4. Первые команды

Вводите их **по одной**:

```powershell
Get-Location
Get-ChildItem
Get-ChildItem -Path $HOME
Get-Date
```

| Команда | Что означает |
| --- | --- |
| `Get-Location` | Где я сейчас нахожусь? |
| `Get-ChildItem` | Какие файлы и папки находятся здесь? |
| `Get-ChildItem -Path $HOME` | Что находится в моей домашней папке? |
| `Set-Location ..` | Перейти на уровень выше. |
| `Get-Date` | Узнать дату и время компьютера. |
| `Get-Process` | Посмотреть запущенные процессы. |

`$HOME` — **переменная**, содержащая путь к домашней папке пользователя: например, `C:\Users\Anna`. Поэтому в командах не нужно вручную вводить имя пользователя из чужого примера.

### Создадим папку Projects

```powershell
New-Item -ItemType Directory -Path "$HOME\Projects" -Force
Set-Location "$HOME\Projects"
Get-Location
Get-ChildItem
```

Первая команда создаст папку `Projects`, если её ещё нет. В данном случае `-Force` позволяет работать и с уже существующим каталогом. Вторая команда перейдёт в папку; третья и четвёртая помогут проверить результат. **Пустой вывод** последней команды нормален, если папка ещё не содержит файлов.

Наша текущая папка влияет на дальнейшие команды, например на то, где Git будет искать репозиторий.

## 5. Основы синтаксиса

Команда PowerShell часто выглядит так:

```text
Глагол-Существительное -Параметр Значение
```

Рассмотрим пример:

```powershell
Get-ChildItem -Path "$HOME\Projects" -File
```

- `Get-ChildItem` — **имя команды**: показать содержимое.
- `-Path` — **имя параметра**: какую папку рассматривать.
- `"$HOME\Projects"` — **значение параметра**: путь к папке.
- `-File` — **переключатель** без отдельного значения: показать только файлы.

Встроенные команды часто именуются по схеме **Verb-Noun** («глагол—существительное»): `Get-Process` (получить процессы), `Get-Content` (прочитать файл), `Set-Location` (перейти в папку), `New-Item` (создать объект). В именах команд и параметров регистр букв обычно не важен: `Get-Date` и `get-date` работают одинаково.

### Кавычки и пути

Пути с пробелами нужно заключать в кавычки:

```powershell
Set-Location "C:\Users\Anna\My Projects"
```

**Двойные кавычки** позволяют подставлять значение переменной; **одинарные** сохраняют буквальный текст:

```powershell
$name = "Анна"
Write-Output "Привет, $name!"
Write-Output 'Привет, $name!'
```

Вторая строка выведет имя; третья — буквальные символы `$name`.

Полезные обозначения: `.` — текущая папка, `..` — родительская, `.\notes.txt` — файл в текущей папке, `$HOME` — домашняя папка.

## 6. А как же Command Prompt, Git Bash и Git?

| Название | Что это | Пример |
| --- | --- | --- |
| **Windows PowerShell** | Оболочка и язык автоматизации | `Get-ChildItem` |
| **Command Prompt** (`cmd.exe`) | Старая командная оболочка Windows | `dir` |
| **Git Bash** | Оболочка Bash и Unix-подобные утилиты, устанавливаемые с Git for Windows | `ls` |
| **Git** | Отдельная программа для работы с историей изменений | `git status` |

В PowerShell можно использовать знакомые сокращения:

```powershell
dir
cd ..
pwd
```

Это **псевдонимы (aliases)** команд `Get-ChildItem`, `Set-Location` и `Get-Location`. Но одинаковое имя в PowerShell, Bash и `cmd.exe` **не гарантирует одинакового поведения**. Например, в Windows PowerShell 5.1 `curl` часто является псевдонимом `Invoke-WebRequest`, а `curl.exe` — отдельной программой.

**Git не является частью PowerShell.** После установки Git for Windows с добавлением Git в `PATH` можно выполнять `git` из обычного PowerShell. Git Bash специально для этого открывать не нужно.

## 7. Главная особенность: конвейер объектов

PowerShell-команды часто передают друг другу не обычный текст, а **объекты** с полями: именем, размером, датой, идентификатором и т. д. Символ `|` называется **конвейером** (*pipeline*) и означает «передай результат следующей команде».

```powershell
Get-Process | Select-Object -First 5 -Property ProcessName, Id
```

`Get-Process` получает сведения о запущенных процессах, а `Select-Object` оставляет первые пять и показывает только поля `ProcessName` и `Id`. Это **просмотр**, а не остановка процессов.

Пример фильтрации Markdown-файлов:

```powershell
Get-ChildItem -Path "$HOME\Projects" -File |
    Where-Object { $_.Extension -eq ".md" } |
    Select-Object -ExpandProperty Name
```

- `Get-ChildItem` получает файлы.
- `Where-Object` оставляет объекты с нужным условием.
- `$_` — **текущий объект**, рассматриваемый в фильтре.
- `.Extension` — его свойство «расширение файла».
- `-eq` — «равно».
- `Select-Object` выводит имена файлов.

Если `.md`-файлов нет, на экране ничего не появится: это **не ошибка**. Запись на нескольких строках всё ещё образует **одну цепочку**.

> Внешние программы, такие как `git.exe`, обычно выводят **текст**, а не такие PowerShell-объекты. Поэтому нельзя автоматически обращаться к их выводу по свойствам, как к результату `Get-Process`.

## 8. PowerShell как язык программирования

**Переменная** хранит значение:

```powershell
$project = "Мой первый проект"
Write-Output $project
```

**Условие** выбирает действие:

```powershell
if (Test-Path "$HOME\Projects") {
    Write-Output "Папка Projects существует."
} else {
    Write-Output "Папки пока нет."
}
```

**Цикл** повторяет действие:

```powershell
foreach ($number in 1, 2, 3) {
    Write-Output "Номер: $number"
}
```

**Комментарий** начинается с `#` и не выполняется:

```powershell
# Это пояснение для человека
Get-Date
```

В будущем эти конструкции можно сохранять в сценариях `.ps1`. Пока достаточно выполнять примеры вручную.

В Windows есть настройка **Execution Policy**, которая определяет условия запуска сценариев. Это защитный механизм, но **не полноценная граница безопасности**. Ради данного урока **не нужно** менять Execution Policy, включать `Bypass` или получать права администратора.

## 9. Как PowerShell связан с Git и Codex

При вводе:

```powershell
git --version
```

PowerShell находит установленную программу Git (`git.exe`), запускает её и показывает ответ. Для выполнения `git status` нужно сначала перейти **в папку своего Git-репозитория**:

```powershell
Set-Location "$HOME\Projects\ИМЯ_РЕПОЗИТОРИЯ"
git status
```

Подставьте вместо `ИМЯ_РЕПОЗИТОРИЯ` имя своей существующей папки.

Запомните различия:

- **PowerShell** — среда, в которой вводятся команды.
- **Git** — программа, управляющая изменениями проекта.
- **GitHub** — интернет-сервис для хранения репозиториев.
- **Codex** — помощник, который может работать с файлами проекта и запускать разрешённые команды.

**Git Credential Manager** может помогать Git авторизоваться на GitHub. PowerShell **не является** отдельным хранилищем паролей GitHub.

## 10. Как находить новые команды

Не нужно заучивать тысячи названий. PowerShell умеет помогать:

```powershell
Get-Command Get-ChildItem
Get-Help Get-ChildItem -Examples
Get-Alias dir
Get-Process | Get-Member
```

`Get-Command` показывает сведения о команде; `Get-Help` — справку и примеры; `Get-Alias` раскрывает сокращение; `Get-Member` показывает свойства объектов. Подробную справку иногда нужно отдельно скачать, но для первых упражнений этого не требуется.

## 11. Правила безопасности

- Открывайте обычный PowerShell, **не от администратора**, если повышение прав не требуется.
- Не вставляйте команды из интернета или ответов ИИ, пока не понимаете, **что они сделают**.
- Особая осторожность нужна с `Remove-Item`, `Format-Volume` и командами «скачать код и сразу выполнить».
- `Get-*` чаще используется для просмотра, а `New-*`, `Set-*`, `Remove-*` — для изменений, но имя команды само по себе **не гарантирует** отсутствие побочных эффектов.
- В командах перенаправления `>` может **перезаписать файл**, а `>>` — добавить текст. Это не тот же `>`, который видно в приглашении `PS ...>`.
- Перед действиями с файлами и Git проверяйте папку через `Get-Location`.
- Если возникла ошибка, сначала **прочитайте её**, а не пробуйте случайные команды.

## 12. Практика и самопроверка

Выполните команды в **обычном Windows PowerShell**:

```powershell
$PSVersionTable.PSVersion
Get-Location
Get-Date
New-Item -ItemType Directory -Path "$HOME\Projects" -Force
Get-ChildItem -Path "$HOME\Projects"
Get-Command git
git --version
```

Последние две сработают только при установленном и доступном в `PATH` **Git for Windows**. Если Git ещё не установлен, вернитесь к [уроку 0](../../LESSON-00.md).

**Проверьте себя:**

1. Чем отличается терминал от оболочки?
2. Что означает `Get-Location`?
3. Что такое параметр `-Path`? А значение `"$HOME\Projects"`?
4. Зачем заключать путь с пробелами в кавычки?
5. Для чего используется символ `|`?
6. Почему `git status` — не встроенная команда PowerShell?
7. Почему для первого урока не нужно устанавливать PowerShell 7?
8. Что делать, если Codex предлагает непонятную команду, меняющую файлы?

**Урок освоен**, если вы умеете открыть PowerShell, посмотреть текущую папку, перечислить файлы, перейти в другую папку и объяснить роль Git.

Вернуться к [уроку 0](../../LESSON-00.md) или [другим дополнительным материалам](../README.md).
