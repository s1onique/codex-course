## Шаг 1. Predict — сначала предсказываем (10 минут)

### Что мы собираемся сделать

В Уроке 08 мы получили массив из трёх **объектов-задач**:

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false }
];
```

А на странице показываются только **две** задачи, и обе — **написаны руками**:

```javascript
  const secondTask = document.querySelector('#second-task');
  const firstTaskStatus = document.querySelector('#first-task-status');

  if (secondTask) {
    secondTask.textContent = tasks[1].title;
  }
```

Проблема очевидна: добавьте пятую задачу — и на странице её не будет. Чтобы показать **любое** число задач, нужен код, который **повторит** одно и то же действие для каждого элемента массива. Такой код называется **циклом**.

### Самый маленький цикл, который нам понадобится

Цикл `for...of` делает ровно одну вещь: **берёт очередной элемент массива и выполняет тело цикла для него**. Пока элементы не кончились — тело выполняется снова.

```javascript
for (const task of tasks) {
  console.log(task.title);
}
```

Разберём по словам, **до** запуска:

| Часть кода | Что значит по-человечески |
|---|---|
| `tasks` | тот самый массив, который у нас уже есть |
| `of tasks` | «**по** элементам массива `tasks`» |
| `const task` | «назови текущий элемент словом `task`» |
| `{ ... }` | **тело цикла** — то, что повторяется |
| `console.log(task.title)` | одна операция: напечатать название текущей задачи |

Ключевое слово здесь — **«по»**. `for...of` говорит: «сделай тело цикла **для каждого** элемента `tasks`».

> **Важное различие.** `for...of` даёт нам **значения** — сами объекты-задачи. Не номера. Поэтому мы пишем `task.title`, а не `task[0].title`. Нумерацию элементов мы сегодня не изучаем.

### 2. Замените ручной показ на список, построенный из данных

Вот главный шаг урока. Сейчас на странице **две** задачи, показанные руками. Мы заменим их на **список**, который создаётся из самого массива.

#### HTML — замените блок, а не добавьте второй

Найдите в своём файле **существующий** блок «Ближайшая задача» (тот, что остался с Урока 08) и **замените его целиком** на этот:

```html
<section class="tasks-preview">
  <h2>Задачи</h2>
  <ul id="task-list"></ul>
  <p>Всего задач: <span id="task-count">—</span></p>
</section>
```

> **Это замена, а не добавление.** В файле должен остаться **ровно один** блок со списком задач. Если вы просто вставите новый `<section>` ниже старого, на странице окажутся **два** блока: старый — с ручными «Первая задача» и «Вторая задача», новый — со списком. Старый блок нужно **удалить**, а не оставить рядом.
>
> **Что исчезает и почему.** Строки `#first-task`, `#second-task` и `#first-task-status` больше **не нужны**: список показывает и названия, и состояние каждой задачи, и делает это для **любого** числа задач. Строка `#task-count` **остаётся** — количество задач мы по-прежнему показываем.

#### JavaScript — напишите функцию показа

Добавьте в свой файл **отдельную функцию** — по правилам Урока 05, где мы выносили повторяющийся расчёт в функцию с именем:

```javascript
function renderTaskList() {
  const list = document.querySelector('#task-list');

  if (!list) {
    console.error('Не найден список задач');
    return;
  }

  list.textContent = '';

  for (const task of tasks) {
    const item = document.createElement('li');

    if (task.done) {
      item.textContent = task.title + ' — Выполнена';
    } else {
      item.textContent = task.title + ' — Не выполнена';
    }

    list.appendChild(item);
  }
}
```

Что здесь происходит — **по порядку**:

| Строка | Зачем она |
|---|---|
| `const list = document.querySelector('#task-list');` | находим на странице наш `<ul>` — тот самый приём из Урока 06 |
| `if (!list) { console.error(...); return; }` | если блока нет — **говорим об этом** и выходим. Страница не должна падать из-за списка |
| `list.textContent = '';` | **очищаем** список перед заполнением — иначе при повторном вызове пункты задвоятся |
| `for (const task of tasks) { ... }` | **тот самый цикл**: один проход на каждую задачу |
| `document.createElement('li')` | создаём **один** элемент списка для текущей задачи |
| `item.textContent = task.title + ' — Выполнена';` | пишем **текстом** — как в Уроке 08 |
| `list.appendChild(item);` | **вставляем** созданный пункт в конец списка |

> **Два новых слова — только на этом шаге.** `createElement('li')` — «создай элемент списка»; `appendChild(item)` — «вставь его в конец списка». Это **минимальные** операции с DOM, которые нужны, чтобы построить список. Отдельной темой они не являются: цель шага — **цикл**, а не API браузера.
>
> **Почему `textContent`, а не `innerHTML`?** Ровно та же причина, что в Уроке 08: название задачи — это **текст**, и его нужно показать **как текст**. Если бы мы вставляли названия через `innerHTML`, строка вида `<b>важно</b>` превратилась бы в **разметку**. `textContent` вставляет именно символы.

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Что такое цикл

Цикл — это **одна и та же операция, повторённая несколько раз**. В нашем случае операция одна: «взять очередную задачу и показать её». Повторяется она столько раз, сколько задач в массиве.

| Понятие | Что это | В нашем коде |
|---|---|---|
| **Цикл** | повторение одной операции | `for (const task of tasks) { ... }` |
| **Тело цикла** | то, что повторяется | всё, что внутри `{ ... }` |
| **Текущий элемент** | элемент, который обрабатывается **сейчас** | `task` |
| **Коллекция** | то, по чему мы идём | `tasks` |

### Что делает `for...of` — по шагам

Когда выполняется `for (const task of tasks)`, происходит вот что:

1. Берётся **первый** элемент `tasks` — объект `{ title: 'Прочитать главу', done: false }`.
2. Он объявляется как `task`.
3. Выполняется **тело цикла** с этим `task`.
4. Берётся **второй** элемент, снова объявляется как `task`, снова выполняется тело.
5. И так, пока элементы не закончились.

`task` — это **одно и то же имя**, которое на каждом шаге указывает на **разный** объект. Поэтому код внутри цикла один и тот же, а работает с разными задачами.

### Почему `for...of` даёт значения, а не номера

Мы уже знаем (Урок 06), что элементы массива лежат под номерами: `tasks[0]`, `tasks[1]`, `tasks[2]`. Можно представить, что «по номеру» — это другой способ пройти тот же массив.

`for...of` выбрал **другой** путь: он кладёт в `task` **сам элемент**, а не его номер. Поэтому мы пишем:

```javascript
task.title
```

а не `task[0].title`. Если бы `task` был номером, то `task.title` не имело бы смысла.

> **Почему это удобно.** Нам не нужен номер: мы показываем **все** задачи, и номер не используется нигде. `for...of` избавляет от лишнего посредника.

### Почему три объекта дают три пункта списка

В теле цикла **две** операции: создать `<li>` и вставить его в список. Тело выполнилось **три** раза — значит, создано **три** элемента `<li>` и вставлено **три**. Ровно столько, сколько задач в массиве.

Связь простая:

| В массиве | Повторений тела | Пунктов в списке |
|---|---|---|
| 0 задач | 0 | 0 |
| 1 задача | 1 | 1 |
| 3 задачи | 3 | 3 |
| 4 задачи | 4 | 4 |

### Почему порядок на странице совпадает с порядком в массиве

Массив — **упорядоченная** коллекция: сначала элемент `0`, потом `1`, потом `2`. `for...of` идёт по массиву **в этом порядке** и добавляет пункты в конец списка **в том же порядке**. Поэтому список на странице повторяет порядок данных.

> **Это важно.** Значит, чтобы поменять порядок задач на странице, нужно менять **данные**, а не код показа. Код показа не «решает», в каком порядке показывать — он показывает в том порядке, в каком получил.

### Что будет, если массив пуст

Тело цикла **не выполнится ни разу**. Значит:

- в консоли не будет **ни одной** строки;
- в списке не будет **ни одного** пункта;
- но строка «Всего задач» всё равно покажет `0` — она читает `tasks.length`, а не считает пункты.

Это не ошибка, а **законное** поведение: обработать нечего — делать нечего.

### Почему старый ручной показ не масштабировался

Сравним два подхода:

| | Ручной показ (Урок 08) | Список из цикла (Урок 09) |
|---|---|---|
| Сколько строк кода | по одной на задачу | **одна** на любое число задач |
| Три задачи | 3 строки | 1 строка + цикл |
| Двадцать задач | 20 строк | **те же** 1 строка + цикл |
| Новая задача | надо **писать** новую строку | просто **добавьте** объект в массив |
| Пустой массив | старая строка всё равно пишет `undefined` | список просто **пуст** |

Главное отличие — не в длине кода, а в **том, откуда берутся названия**. В ручном показе названия **записаны в коде** (`tasks[0].title`, `tasks[1].title`) — программа показывает «первую» и «вторую», а не «все». В цикле названия берутся **из данных**: программа проходит по массиву и показывает **каждый** элемент. Поэтому список остаётся правильным, когда массив меняется.

### Данные, показ и порядок — три разные вещи

Как и в Уроках 07–08, полезно держать в голове разделение:

- **Данные** — массив `tasks`: сколько задач, какие у них названия и состояния.
- **Показ** — функция `renderTaskList()`: превращает данные в пункты списка.
- **Порядок** — свойство самих данных: в каком порядке задачи лежат в массиве.

Код показа **не решает**, что показывать и в каком порядке. Он делает ровно одно: **проходит по данным и показывает каждый элемент**. Правило простое: **чтобы изменить, что показано, — меняйте данные**.

## Шаг 4. Modify — добавляем четвёртую задачу (15 минут)

### Что мы собираемся сделать

Проверим, что список действительно строится **из данных**: добавим задачу в массив — и посмотрим, появится ли она в списке сама.

### Запишите предсказания ДО запуска

**Предсказание 1.** Добавьте в **свой файл** четвёртую задачу-объект (например, `{ title: 'Написать отчёт', done: false }`) — любым из двух способов, которые вы знаете: **внутрь** литерала массива **или** отдельным вызовом `push()` **с объектом**.

**Важно:** не делайте оба сразу — иначе задача попадёт в массив дважды.

**Предсказание 2.** После добавления задачи и перезагрузки страницы:

- Сколько пунктов будет в списке? ___
- В каком порядке они будут идти? ___
- Какое будет **последнее** название? ___
- Что покажет строка «Всего задач»? ___
- Сколько раз выполнится тело цикла? ___

**Предсказание 3.** Теперь измените состояние **второй** задачи: `done: true`. Что изменится в её пункте списка?

- Само название? ___
- Приписка в конце пункта? ___

| Что | Ваше предсказание | Что показала страница | Совпало? |
|---|---|---|---|
| Число пунктов списка | | | ☐ |
| Последнее название | | | ☐ |
| «Всего задач» | | | ☐ |
| Приписка у второй задачи | | | ☐ |

### Выполните

1. Добавьте четвёртую задачу в **файл**.
2. **Сохраните** файл.
3. **Обновите** страницу (`F5`).
4. Посмотрите на список и на строку «Всего задач».

| Что | Ожидаемо | Совпало? |
|---|---|---|
| Число пунктов списка | `4` | ☐ |
| Порядок названий | как в массиве | ☐ |
| «Всего задач» | `4` | ☐ |
| Дублей в списке | **нет** | ☐ |
| Старых строк «Первая задача» | **нет** | ☐ |

### Измените состояние одной задачи

1. В файле поменяйте у **второй** задачи `done: false` на `done: true`.
2. **Сохраните** файл и обновите страницу (`F5`).
3. У пункта второй задачи теперь должно быть `— Выполнена` вместо `— Не выполнена`. Название — то же.

> **Почему без перезагрузки ничего не изменится.** Функция `renderTaskList()` вызывается **один раз** — при загрузке страницы. Она **записала** текст пунктов в этот момент. Если вы изменили `done` в консоли, данные изменятся, а текст в списке останется прежним: показ не пересчитывается сам. Это та же разница между **данными** и **показанным текстом**, что мы разбирали в Уроках 07 и 08. В Уроке 10 мы научимся обновлять список после изменения состояния — а пока правильный способ такой: изменили файл → сохранили → обновили страницу.

### Верните исходное состояние

Верните массив к **трём** задачам (уберите четвёртую) и верните у второй задачи `done: false`. Сохраните и обновите страницу: список снова из трёх пунктов, «Всего задач» — `3`.

> **Если у вас была своя четвёртая задача из Урока 08** — верните **её**, а не выбрасывайте. Канонический путь урока — три задачи, но ваша задача не помешает.

> **Проверка на «всё живое».** Нажмите кнопку счётчика, кнопку оформления, проверьте блок «Пример задачи». Ничего не должно сломаться.

## Что вы теперь умеете

| Раньше | Теперь |
|---|---|
| Названия задач **записаны в коде** | Список **строится из данных** |
| Три задачи — три строки кода | Любое число задач — **та же** одна строка + цикл |
| Показаны только первая и вторая | Показаны **все** |
| Новая задача — писать новую строку | Новая задача — **добавить объект** в массив |
| Порядок показа задан кодом | Порядок показа **совпадает с порядком данных** |

**Что осталось на потом.** Мы научились проходить по всем задачам и показывать их. Но пока список строится **один раз** — при загрузке страницы. Если задачу отметить выполненной, данные изменятся, а показанный текст останется прежним: чтобы обновить список, страницу приходится перезагружать. В следующем уроке мы научимся **менять состояние задачи и обновлять список после этого** — и постепенно отделим «изменение данных» от «показа данных».

## Критерий завершения урока

Урок пройден, если вы **самостоятельно**:

1. Объяснили своими словами, что такое цикл, тело цикла и текущий элемент.
2. Написали цикл `for...of` по массиву `tasks` и объяснили, что он делает.
3. **Предсказали** число повторений и порядок вывода для трёх, четырёх и нуля задач — **до** запуска кода.
4. Объяснили, почему `for...of` даёт **значения**, а не номера, и почему мы пишем `task.title`.
5. **Заменили** ручной показ первой и второй задач на список, который строится **из массива** — и удалили старые строки «Первая задача», «Вторая задача», «Первая задача выполнена».
6. Объяснили, почему три задачи дают три пункта списка, а пустой массив — ноль.
7. Объяснили, почему старый ручной показ не масштабировался, а список — масштабируется.
8. Добавили четвёртую задачу **в файл**, сохранили, обновили страницу и увидели **четыре** пункта в правильном порядке, без дублей, с «Всего задач» — `4`.
9. Изменили `done` у одной задачи и увидели, что приписка в её пункте стала `— Выполнена`.
10. Убедились, что счётчик, сообщение, кнопка оформления и блок «Пример задачи» из Урока 07 работают как раньше.
11. **Вернули исходное состояние**: массив из трёх задач, все `done: false`.

Шаг Make, необязательная четвёртая задача и упражнение `points` из Урока 03 — **необязательные**.

Если что-то не получилось, запишите это прямо. **Не выдавайте ожидаемый результат за фактический** — это главный навык всего курса.

## Источники подхода

Урок построен по схеме **PRIMM** (Predict → Run → Investigate → Modify → Make): [primmportal.com](https://primmportal.com/). Шаги Predict и Modify учат связывать выражение с наблюдаемым результатом и предсказывать состояние до изменения; порядок «сначала предсказать, потом запустить» опирается на исследования чтения и трассировки кода новичками (Busjahn & Schulte, 2013; Lister et al., 2004, 2009), перечисленные на странице [Research](https://primmportal.com/research/).

Идея урока — **последовательное усложнение одного и того же проекта**: ученик не переписывает приложение, а заменяет ручной показ отдельных задач показом, построенным из данных, и наблюдает, что список остаётся правильным при изменении массива. Это соответствует позиции курса: изменение способа показа — обычная инженерная работа, и навык «заменить ручное перечисление обходом коллекции» важнее, чем новый синтаксис. Различение «наблюдения», «проверки контракта» и «формального доказательства» соответствует подходу курса (см. [CURRICULUM-DESIGN.md](CURRICULUM-DESIGN.md), раздел D.1a).
