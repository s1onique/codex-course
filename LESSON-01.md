# Урок 1. Знакомство с Codex: от идеи до работающей страницы

**Время:** 60–75 минут  
**Уровень:** начинающий  
**Нужно:** установленный Codex, вход через аккаунт ChatGPT, существующий GitHub-репозиторий и веб-браузер.  
**Результат:** небольшая интерактивная страница, которую можно открыть на своём компьютере.

## Чему научимся

После урока вы сможете:

1. Объяснить разницу между обычным AI-чатом и кодинговым агентом.
2. Показать Codex папку своего проекта и попросить его разобраться в файлах.
3. Поручить небольшую работу с понятными границами.
4. Отличить сообщение «готово» от действительно проверенного результата.
5. Увидеть, какие файлы агент создал или изменил.

### Главная идея

**В обычном чате вы часто получаете совет или кусок кода. Codex может работать с файлами проекта, запускать доступные инструменты и помогать проверять результат.** Но действия зависят от выбранной среды и разрешений, а его утверждения всё равно нужно проверять.

В этой работе у вас две роли: **вы определяете цель и проверяете результат**, Codex предлагает и выполняет технические шаги.

## Шаг 1. Открываем правильный проект (10 минут)

GitHub и папка на компьютере — не одно и то же. **GitHub-репозиторий** — копия проекта на удалённом сервисе. **Локальный репозиторий** — папка с проектом на вашем компьютере; в ней Codex может создавать и менять файлы.

Если папка проекта уже есть на компьютере, откройте её в Codex. Если проект пока есть только на GitHub, сначала скопируйте (клонируйте) репозиторий на компьютер. Это можно сделать через GitHub Desktop или, если Git уже настроен, из терминала:

```sh
git clone https://github.com/USERNAME/REPOSITORY.git
cd REPOSITORY
```

Замените `USERNAME/REPOSITORY` реальным адресом своего репозитория. Если доступ не настроен, не создавайте ради первого урока персональный токен с широкими правами: используйте уже настроенную авторизацию или обратитесь за помощью.

**В приложении Codex / ChatGPT Desktop:** создайте или откройте локальный проект, выберите папку репозитория и начните новую задачу Codex. **В Codex CLI:** откройте терминал внутри папки репозитория и выполните `codex`, затем при необходимости войдите через ChatGPT.

> Важно: выбор папки определяет, с какими файлами будет работать агент. Убедитесь, что выбрана именно учебная папка, а не, например, вся домашняя директория.

## Шаг 2. Сначала знакомимся, ничего не меняя (10 минут)

Скопируйте в Codex этот запрос:

```text
Это мой учебный Git-репозиторий. Пока ничего не изменяй.

1. Сообщи, с какой папкой ты работаешь, и какая сейчас ветка Git.
2. Кратко объясни, для чего нужны основные файлы и папки.
3. Проверь, есть ли несохранённые в Git изменения.
4. Проверь, существует ли путь practice/lesson-01/index.html.
5. Скажи, можно ли безопасно добавить там учебную страницу.

Не меняй файлы, не устанавливай программы, не удаляй ничего,
не делай commit или push и не отправляй данные внешним сервисам.
Если чего-то не можешь проверить, скажи об этом прямо.
Ответь по-русски, кратко и без сложных терминов.
```

**Проверьте ответ:** Codex должен назвать настоящую папку, а не угадать её, и сообщить, есть ли уже изменения или нужный файл. Если в репозитории есть незакоммиченные изменения, сначала разберитесь с ними; не разрешайте «навести порядок» удалением или перезаписью. Если `practice/lesson-01/index.html` уже существует, выберите другое имя и скорректируйте задание ниже.

Это и есть первый навык: **сначала посмотреть на состояние проекта, потом изменять его**.

## Шаг 3. Делаем первую страницу (15–20 минут)

Мы создадим одностраничный мини-сайт. Для него не нужны сервер, база данных, регистрация, API и установка библиотек. Веб-браузер умеет открывать обычный HTML-файл.

Скопируйте следующий запрос:

```text
Создай мой первый маленький веб-проект в существующем репозитории.

Цель: красивая, дружелюбная страница «Мой первый проект с Codex».

Что должно быть на странице:
- заголовок и короткое приветствие;
- три карточки: «Что мне интересно», «Чему хочу научиться»,
  «Моя идея для следующего проекта»;
- кнопка «Поменять оформление», которая переключает два
  заметно разных варианта оформления страницы;
- аккуратный вид на широком и узком экране.

Ограничения:
- создай только practice/lesson-01/index.html и необходимые папки;
- все HTML, CSS и JavaScript помести в этот один файл;
- не используй внешние библиотеки, CDN, API или изображения;
- не меняй другие файлы проекта;
- не делай commit, push и публикацию;
- если файл уже существует или есть риск затронуть чужие изменения,
  остановись и объясни проблему.

После работы:
1. Назови созданные и изменённые файлы.
2. Объясни, как открыть страницу в браузере.
3. Сообщи, что именно удалось проверить, а что не проверялось.
```

**Почему запрос устроен именно так?** Здесь есть цель, видимый результат, ограничения и способ проверки. Агенту не нужно угадывать, хотите вы большой коммерческий сайт или учебную страницу. И он не получает разрешения менять весь репозиторий.

## Шаг 4. Проверяем сами (10–15 минут)

Откройте файл `practice/lesson-01/index.html` в браузере: обычно достаточно дважды щёлкнуть по нему в файловом менеджере. Не путайте его с файлом на GitHub: пока изменения локальные, удалённый репозиторий их ещё не содержит.

Отметьте выполненные проверки:

- [ ] Заголовок и три карточки действительно видны.
- [ ] Кнопка меняет оформление после нажатия.
- [ ] При повторном нажатии оформление меняется обратно.
- [ ] При уменьшении окна карточки остаются читаемыми.
- [ ] Для просмотра страницы не требуется регистрация или платный сервис.

Если что-то не работает, не начинайте всё с нуля. Вернитесь в Codex и опишите **фактически наблюдаемую проблему**. Например:

```text
В браузере страница открылась, но кнопка «Поменять оформление»
ничего не меняет. Найди причину. Исправь только файлы урока 1.
После исправления объясни, как я могу самостоятельно
проверить, что ошибка исчезла.
```

Если Codex пишет, что всё проверено, полезно спросить: **«Каким способом ты это проверил? Что реально запускал и какой результат увидел?»** Если агент не мог открыть браузер, его вывод о визуальной работе — предположение, а не проверка.

## Шаг 5. Что именно изменилось? (10 минут)

Попросите Codex:

```text
Покажи краткую сводку изменений относительно исходного состояния.
Какие файлы появились? Какие существующие файлы изменились?
Объясни простыми словами, где находятся:
- содержимое страницы;
- оформление;
- поведение кнопки.

Ничего сейчас не меняй и не делай commit или push.
```

В интерфейсе Codex найдите просмотр созданных или изменённых файлов. Если используете терминал, `git status --short` покажет состояние файлов; для **нового, ещё не добавленного в Git** файла обычный `git diff` может ничего не показать — откройте сам файл или воспользуйтесь просмотром изменений в приложении.

Запомните три новых слова:

| Термин | Что означает |
|---|---|
| **HTML** | Что находится на странице: заголовки, текст, карточки, кнопки |
| **CSS** | Как страница выглядит: цвета, размеры и расположение |
| **JavaScript** | Что происходит при действии: например, при нажатии кнопки |

Пока не нужно учить синтаксис. Важно понимать эти различия, чтобы точнее формулировать следующую задачу.

## Дополнительно: сохраним на GitHub (необязательно, 10 минут)

Изменение локального файла **ещё не означает**, что оно появилось на GitHub. Для этого обычно нужно создать ветку, сделать коммит и отправить его (`push`). Подробно мы изучим это на уроке 3.

Если вы уже уверенно пользуетесь Git и убедились, что чужие изменения не затронуты, можете попросить Codex **предложить** команды для отдельной ветки `lesson/01-first-page`, одного коммита только с учебным файлом и отправки ветки на GitHub. Выполняйте эти действия только после проверки списка файлов и явного подтверждения. Не нужно отправлять изменение прямо в `main` ради первого урока.

## Домашнее задание (5–10 минут)

Самостоятельно попросите Codex изменить **одну** деталь страницы на ваш вкус: цвет, название карточки или текст кнопки. В запросе укажите, что должно измениться, а что нужно оставить прежним. Откройте страницу и проверьте результат.

## Проверка знаний

1. Чем Codex отличается от обычного чата с ИИ?
2. Почему перед работой полезно узнать, есть ли уже изменения в проекте?
3. Можно ли верить сообщению «готово», не открывая результат?
4. Какая технология отвечает за внешний вид страницы — HTML, CSS или JavaScript?
5. Появится ли локальная правка сама по себе на GitHub?

**Ответы:** (1) агент может работать с файлами и инструментами в пределах доступа; (2) чтобы не потерять чужую работу; (3) нет; (4) CSS; (5) нет, нужна отправка изменений.

## Критерий завершения урока

Урок пройден, если вы **самостоятельно** открыли созданный HTML-файл, увидели три карточки и подтвердили, что кнопка действительно меняет оформление, а Codex смог объяснить, какие файлы создал и что проверил. Если что-то не получилось, зафиксируйте это явно — не выдавайте ожидаемый результат за фактический.
