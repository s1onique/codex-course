## 3. P1 — Исправление семантики регистрации обработчиков

### Подтверждённый дефект

Имитация DOM в `tools/check-lesson-10.mjs` безусловно добавляла каждый
зарегистрированный обработчик:

```javascript
// БЫЛО — неверно
addEventListener(type, handler) {
  listeners.push({ type, handler });
}
```

Настоящий `EventTarget` так не работает: повторная регистрация **той же** функции для
**того же** типа события **игнорируется**.

### Нативный эталон (Node.js `EventTarget`, не имитация)

Исполнено против **настоящего** `EventTarget` из стандартной библиотеки Node.js:

| Сценарий | native `EventTarget` | Старая имитация | Исправленная имитация |
|---|---|---|---|
| Одна и та же функция зарегистрирована дважды | **1** вызов | **2** — неверно | **1** — верно |
| Две разные функции-обёртки | **2** вызова | 2 | **2** — верно |

Отдельное воспроизведение старой семантики (запуск в изолированном скрипте) дало:

```
СТАРАЯ имитация: число обработчиков = 2 (ожидалось 1 по native EventTarget)
native EventTarget: число вызовов = 1

### Исправление

В имитации DOM (`tools/check-lesson-10.mjs` и `tools/check-lesson-11.mjs`) реализована
**только** необходимая курсу семантика:

- тот же тип события + та же функция + тот же флаг `capture` → повторная регистрация
  **игнорируется** (дубликат не добавляется);
- две разные функции → два обработчика, **оба** выполняются при отправке события.

Добавлен `dispatchEvent(type)` — отправка события произвольного типа — чтобы сценарии
сверки можно было прогнать на одном и том же типе события `'test'`.

Общий-purpose DOM **не** строился: имитация по-прежнему покрывает только `textContent`,
`appendChild`, `createElement`, `querySelector` по `id`, `addEventListener` и диспетчеризацию
клика.

### Переписанный NC-3

Прежний NC-3 регистрировал **одну и ту же** функцию `completeFirstTask` два раза. Теперь он
регистрирует **две разные функции-обёртки** — настоящий дубликат:

```javascript
completeButton.addEventListener('click', function () {
  completeFirstTask();
});

completeButton.addEventListener('click', function () {
  completeFirstTask();
});
```

Добавлен **NC-3b** — контроль на ложное срабатывание: повторная регистрация **одной**
функции остаётся **одним** обработчиком, и контракт «один обработчик» **не** ломается.

### Обязательные доказательства NC-3

| № | Требование | Как получено | Результат |
|---|---|---|---|
| 1 | Прежняя имитация ошибочно считает две одинаковые подписки | Отдельный запуск старой семантики | **2** (неверно) |
| 2 | Native-эталон сообщает одну | `new EventTarget()` + `dispatchEvent` | **1** |
| 3 | Исправленная имитация сообщает одну | Тест «нативная семантика EventTarget совпадает с имитацией DOM» | **1** |
| 4 | Две разные обёртки регистрируются дважды | Тест «…по двум разным функциям» | **2** |
| 5 | Контракт числа подписок ловит настоящий дубликат | NC-3: `clickListenerCount() === 2`, `notEqual(…, 1)` | **ломается** |
| 6 | Итоговый `done === true` не отличает двойное выполнение | NC-3: после клика `tasks[0].done === true` | **подтверждено** |

**Приём контроля числа подписок не ослаблен:** он по-прежнему требует ровно один обработчик
и по-прежнему ломается на настоящем дубликате. Добавлен только **дополнительный** контроль
на ложное срабатывание.

### Соответствие названию модели

**Выбор → определение задачи → изменение состояния → обновление списка** реализовано
буквально:

1. **Выбор** — `select.selectedIndex` (позиция выбранного варианта, с нуля).
2. **Определение задачи** — `tasks[index]` (объект-задача из массива).
3. **Изменение состояния** — `tasks[index].done = true`.
4. **Обновление списка** — `renderTaskList()`.

### Новые понятия

| Понятие | Как подано |
|---|---|
| `<select>` | «выпадающий список», выбор одного варианта из нескольких |
| `selectedIndex` | номер позиции с нуля; таблица `0` / `1` / `2` / `-1` |
| Преобразование строки | **не требуется**: `selectedIndex` уже число |

| **Make** (необязательно) | описать, как добавить четвёртую задачу; проверить, добавив её в исходный массив, сохранив и перезагрузив; **не** требуется новый обработчик, уникальные идентификаторы или сохранение данных |

Исполняемых блоков `javascript` в шаге Predict нет — это проверяется тестом.

### Контракт когнитивной нагрузки

- **Один** счастливый путь: существующая кнопка первой задачи → список выбора → выбранный
  индекс → завершение выбранной задачи.
- **Одна** новая ментальная модель: *пользователь выбирает, к какой существующей задаче
  применяется операция*.
- Альтернативных вариантов взаимодействия **не** предлагается.
- Широкая система HTML-форм **не** изучается.
- Переиспользованы только уже знакомые `for...of`, `createElement`, `appendChild`,
  `textContent` и существующая работа с событиями.
- Первое предсказание доступно **без** длинного объяснения API: достаточно таблицы
  `0 / 1 / 2 / -1` и трёх абзацев про `<select>`.
- Необязательная функция `completeTaskByIndex()` из Урока 10 **не требуется**.
