## 3. Закрытие P1 и P2

### P1 — Эксперимент C в Уроке 12 (истинность значения)

**Дефект.** Урок предсказывал, что при `tasks[index].done = 'да'`
канонический показ напишет «— **Не выполнена**», потому что
`if (task.done)` «проверяет логическое значение, а строка `'да'` — это
не `true`».

**Установлено исполнением** (Node.js v26.0.0):

| Выражение | Значение |
|---|---|
| `'да' === true` | `false` |
| `Boolean('да')` | `true` |
| `if (task.done)` → ветка | «Выполнена» |
| `if (task.done === true)` → ветка | «Не выполнена» |

Канонический показ Уроков 09–12 использует `if (task.done)` — проверку
**истинности**. Наблюдаемая надпись — **«— Выполнена»**, **та же**, что и
при правильном результате.

**Исправлено.** Предсказание, наблюдение и объяснение приведены в
соответствие с наблюдённым поведением. Главный вывод сохранён: **инвариант
состояния нарушен** (`done` — не логическое значение), **граница
допустимых изменений выполнена**, **постусловие нарушено**. Добавлена
формулировка: **надпись на странице не доказывает**, что данные имеют
требуемый тип, — проверять надо **сравнением значения**. Лекция о
truthiness и приведении типов в **обязательный** путь ученика **не**
введена.

**Негативный контроль.** `TRUTH-2` **исполняет** оба условия с
`done = 'да'` независимо и убеждается, что результаты **различаются**;
`TRUTH-3` проверяет, что канонический показ в уроке использует именно
`if (task.done)`, а не `if (task.done === true)`.

## 4. Модель Урока 14

### Главная модель

**Входные данные → вычисление → новые данные.**

И она отделена от полной цепочки приложения:

**Событие интерфейса → вычисление → изменение состояния приложения → отображение.**

Урок **не** утверждает, что приложение перестаёт менять состояние. Он
утверждает, что **вычисление** и **внешне наблюдаемое изменение** — это
**разные обязанности**.

### Канонический дизайн

Одна новая чистая функция:

```javascript
function nextTask(task, event)
```

| Что | Значение |
|---|---|
| Вход 1 | объект-задача `{ title, status }` |
| Вход 2 | строка события: `START` или `COMPLETE` |
| Выход | объект `{ accepted: Boolean, task: <объект-задача> }` |

### Таблица переходов — сохранена **точно**

| Текущее состояние | Событие | Принято | Результат |
|---|---|---|---|
| `new` | `START` | `true` | новая задача с `in_progress` |
| `new` | `COMPLETE` | `false` | исходное состояние |
| `in_progress` | `START` | `false` | исходное состояние |
| `in_progress` | `COMPLETE` | `true` | новая задача с `done` |
| `done` | `START` | `false` | исходное состояние |
| `done` | `COMPLETE` | `true` | неизменённый `done` |

Таблица Урока 13 **не изменена** — это проверяется `P-TABLE-1` и
`P-TABLE-2` в `tools/check-lesson-14.mjs` (сравнение с **самим**
`LESSON-13.md`).

### Контракт чистоты `nextTask()`

| Требование | Как обеспечено |
|---|---|
| Зависит только от аргументов | нет обращений к `tasks`, `window`, `document` |
| Не изменяет входную задачу | создаёт **новый** объект вместо присваивания |
| Не читает и не пишет глобальный `tasks` | проверено исполнением (`P8`) |
| Не обращается к `document`, `window`, консоли | проверено по исходнику |
| Не регистрирует событий | проверено по исходнику |
| Не делает ввод-вывод | проверено по исходнику |
| Эквивалентные входы → эквивалентные значения | проверено исполнением (`P7`) |
| Сохраняет название задачи | `title: task.title` во всех шести строках |
| Сохраняет исходное состояние входа | проверено исполнением (`P4`) |

**Точность формулировки.** Для переходов, которые **действительно**
меняют состояние, создаётся **новый** объект-задача. Для отклонённых
событий и принятого «вхолостую» перехода **разрешено** вернуть исходный
объект — мутации не происходит. Урок прямо говорит: **чистота не требует
выделять новый объект, когда ничего не нужно менять**.

### Граница модели данных

Каноническая схема задачи — **ровно** `{ title: string, status: string }`.
Поля копируются **явно**, уже знакомым синтаксисом объектного литерала.
Не введены: spread-оператор, библиотеки копирования, вложенные структуры,
универсальные утилиты копирования. Урок объясняет, что при расширении
схемы **правило копирования придётся пересмотреть**.

### Референциальная прозрачность — только через значения

Введена **только** через эквивалентность **значений**: одинаковые входы →
одинаковые значения результата. Урок прямо говорит, что два вызова
создают **разные** объекты, и что сравнение объектов по ссылке — **другая**
тема. Формальное лямбда-исчисление и эквациональные рассуждения **не**
вводятся.

### Разделение ответственности

`transitionTask(index, event)` **сохраняется** как публичная операция и
**по-прежнему возвращает Boolean**. Её обязанности:

1. проверить номер;
2. прочитать текущую задачу;
3. вызвать `nextTask(currentTask, event)`;
4. отказать при `accepted === false`;
5. при принятии положить возвращённую задачу в массив;
6. вернуть `true`.

Обёртка **намеренно нечиста**: она обновляет состояние приложения.
`completeSelectedTask()` остаётся функцией оркестрации интерфейса, её
контракт подписки **не меняется**.

> **Одна функция владеет правилами; обёртка применяет решение.** Второй
> независимой реализации правил FSM в уроке **нет** — это проверяется
> проверкой «в обёртке нет сравнений со состояниями и нет присваиваний
> `status`» в `tools/check-lesson-14.mjs`.
