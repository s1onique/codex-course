## 6. Урок 10 — цели и реализация

**Файл:** `LESSON-10.md` (создан).
**Заголовок:** «Урок 10. Изменение состояния: отмечаем задачу выполненной».
**Оценка времени:** 45–75 минут. **Пререквизиты:** Уроки 00–09 (все десять файлов существуют, ссылки относительные и разрешаются).

### Цель урока

Ученик может объяснить и реализовать контролируемое изменение состояния выполнения задачи, вызвать это изменение кнопкой и обновить показанный список **без перезагрузки страницы**.

### Главная модель

**Событие → изменение состояния → показ → наблюдаемый результат.**
Вспомогательная формулировка: **изменение данных и показ данных — это две разные операции**.

### Введённые понятия

- **Состояние** — текущее значение `done` задачи (`true` / `false`).
- **Переход состояния** — смена одного допустимого значения на другое (`false → true`).
- **Событие, вызывающее функцию изменения состояния** — клик по кнопке.
- **Явный повторный показ** после изменения.
- **Идемпотентность** — объяснена обычным языком: повторное выполнение той же операции оставляет задачу выполненной и не создаёт нового изменения.

### Каноническая функция

```javascript
function completeFirstTask() {
  if (tasks.length === 0) {
    console.error('Нет задач для завершения');
    return;
  }

  tasks[0].done = true;
  renderTaskList();
}
```

### Каноническая кнопка и подключение

```html
  <button id="complete-first-task">
    Завершить первую задачу
  </button>
```

```javascript
  const completeButton = document.querySelector('#complete-first-task');

  if (!completeButton) {
    console.error('Не найдена кнопка завершения задачи');
  } else {
    completeButton.addEventListener('click', completeFirstTask);
  }
```

Подключение — **одно**, в существующем пути инициализации (не внутри `renderTaskList()`), с защищённым поиском и полезной диагностикой.

### Обязательное поведение (исполнено)

| Событие | `tasks[0].done` | Надпись у первого пункта |
|---|---|---|
| Начальная загрузка | `false` | Не выполнена |
| Первое нажатие | `true` | Выполнена |
| Второе нажатие | `true` | Выполнена |
| Третье нажатие | `true` | Выполнена |
| Перезагрузка без сохранения | `false` | Не выполнена |

Вторая и третья задачи не меняются ни при одном нажатии. Если первая задача уже выполнена, кнопка оставляет её выполненной. Функция **не требует** необязательной четвёртой задачи и **не требует** упражнения `points` — проверено отдельными сценариями.

### PRIMM

Порядок шагов: Predict → Run → Investigate → Modify → Make. Первое содержательное предсказание (шесть вопросов) — в начале шага Predict, **до** запуска кода; таблица предсказаний требует заполнить её до выполнения. Шаг Modify (временно `tasks[1]` вместо `tasks[0]`) — с предсказанием до запуска и возвратом к исходному виду. Шаг Make (функция `completeTaskByIndex(index)` с параметром — знание Урока 05) — **необязателен** и явно **не является** условием для Урока 11.

### Чего урок не вводит

Формальная нотация конечных автоматов, состояния кроме `true`/`false`, делегирование событий, кнопка на каждую задачу, `dataset`, `closest()`, разбор индексов из HTML, промисы и асинхронность, классы, персистентность, TypeScript, фреймворки и новое оснащение — перечислены в разделе «Что НЕ понадобится» и проверены статическим аудитом канонического кода в `tools/check-lesson-10.mjs` (тест «урок не вводит запрещённые понятия»).

## 10. Наблюдения по когнитивной нагрузке (V7)

**Одна главная новая модель:** «изменение данных и показ данных — две разные операции», выраженная цепочкой **событие → изменение состояния → показ → наблюдаемый результат**. Всё остальное в уроке — переиспользование уже изученного: булевы значения и условия (Уроки 03–04), функции и параметры (Урок 05), массивы и индексы (Урок 06), свойства объектов (Урок 07), `textContent` (Уроки 07–08), обработчики событий (Уроки 02, 07), `renderTaskList()` (Урок 09).

Наблюдения (качественные, без выдуманных оценок времени выполнения новичком):

- **Дублирование примеров.** Пример «изменение без показа оставляет старый текст» и пример «показ без изменения не завершает задачу» выглядят симметричными и могут быть избыточными. Они оставлены, потому что **каждый закрывает свой вопрос** из критерия завершения (пункт 5) и показывают обе стороны разделения; сокращение дало бы риск пропустить объяснение, ради которого урок написан.
- **Непредставленный синтаксис.** В каноническом коде нет ничего, что не было введено ранее. Новое для ученика — только `console.error` внутри функции (в Уроке 09 ученик уже встречал `console.error` в каноническом `renderTaskList()`) и `String(tasks.length)` (Урок 08). `classList` в тестовой имитации — **не** ученический код: он относится к инструкторскому тесту.
- **Единственная новая лексика:** слова «состояние», «переход состояния», «идемпотентный». Каждое определено явно и появляется раньше, чем используется в задании.
- **Объём:** 3 235 слов против 4 712 (Урок 08) и 4 271 (Урок 09) — урок 10 **короче** соседних при большем числе новых понятий. Основной риск для новичка — не объём, а требование **вспомнить два места** (изменение данных и вызов показа); этому посвящено отдельное рассуждение в шаге Investigate.
- **Шаг Make** вводит параметр-индекс и проверку диапазона — это **необязательный** шаг, и он явно вынесен за пределы критерия завершения и за пределы условий для Урока 11.
- **Скрытых обязательных предпосылок нет:** необязательные `points`, `double()` и четвёртая задача везде помечены как необязательные; Урок 10 не ссылается на Урок 11 как на существующий артефакт.
