## 3. Находки и исправления (P1 / P2)

### P1-1. Неверное объяснение строки «5» — исправлено

**Было (неверно):** «Кавычки важны: `"5"` — это **строка** (пять символов), `5` — это **число**».

**Стало:** `5` — числовой литерал; `"5"` — строковый литерал **из одного символа**; кавычки — **границы** строки, они не входят в её значение; `"5".length` равно `1`.

**Обоснование (исполнено):** `assert.strictEqual("5".length, 1)` → PASS; `typeof "5" === "string"`, `typeof 5 === "number"`.

### P1-2. Упражнение Make не показывало второе значение — исправлено

**Было:** вторая переменная `themeChanges` **увеличивалась**, но **нигде не отображалась** — на странице было **одно** число. Кроме того, она считала те же самые клики, что и `clicks`, то есть дублировала первый счётчик и не давала нового понимания.

**Стало:** вторая переменная — `points` (**2 очка за нажатие**), у неё **свой** элемент вывода `#points`, и оба значения видны на странице.

Минимальные примеры «до / после»:

```html
<!-- было: одно видимое число -->
<span>нажатий: <span id="counter">0</span></span>

<!-- стало: два видимых значения -->
<span>нажатий: <span id="counter">0</span></span>
<span>очков: <span id="points">0</span></span>
```

```javascript
// было: themeChanges считался, но не показывался
clicks = clicks + 1;
themeChanges = themeChanges + 1;
countDisplay.textContent = clicks;

// стало: два значения, два элемента вывода
clicks = clicks + 1;
points = points + 2;
countDisplay.textContent = clicks;
pointsDisplay.textContent = points;
```

Ожидаемое поведение (база `0`, шаг `1`), как в отчёте:

| Нажатий | `clicks` | `points` |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 3 | 6 |

**Обоснование (исполнено):** последовательность `[[0,0],[1,2],[2,4],[3,6]]` получена исполнением кода в Node; DOM-шим подтверждает `counter.textContent === '1'` и `points.textContent === '2'` после одного нажатия, `'3'`/`'6'` после трёх, и что **оба** элемента вывода присутствуют и связаны с **разными** переменными (см. §5, V2/V3).

Дополнительно в примере явно сказано, что приведённый фрагмент — это **замена** старого обработанного куска, а не **второй** блок: две новые строки добавляются **внутрь** существующего обработчика, иначе на странице окажется два обработчика и счётчик будет прыгать через два.

### P1-4. Небезопасный запасной путь — исправлено

**Было:**

```javascript
document.querySelector('button').addEventListener('click', function () { … });
```

Три отказа: (а) `querySelector('button')` берёт **первую** кнопку страницы — при двух кнопках счётчик привязывался не к той; (б) предполагалось, что HTML **уже разобран** к моменту выполнения скрипта; (в) при отсутствии `#counter` код падал; дублирование счётчика не предотвращалось (была только прозаическая просьба).

**Стало:** запасной путь разбит на **три явные правки** и содержит одну детерминированную happy path:

```html
<button id="theme-button">Поменять оформление</button>
…
<span id="counter">0</span>
```

```javascript
let clicks = 0;

const countDisplay = document.querySelector('#counter');
const themeButton = document.querySelector('#theme-button');

function startCounter() {
  themeButton.addEventListener('click', function () {
    clicks = clicks + 1;
    countDisplay.textContent = clicks;
  });
}

if (themeButton && countDisplay) {
  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', startCounter);
  } else {
    startCounter();
  }
}
```

Что это даёт и почему:

| Требование задания | Как выполнено |
|---|---|
| Однозначно идентифицировать кнопку | поиск по `#theme-button` вместо «первой кнопки» |
| Не вешать обработчик на постороннюю кнопку | обработчик вешается **только** на найденную по `id` кнопку |

### P2-1. Определение выражения было неверным — исправлено

**Было:** «**Выражение — это не команда, а вопрос «что получится?»** Команда меняет что-то; выражение просто даёт значение.» — в JavaScript это неверно: присваивание является выражением и меняет состояние.

**Стало:** выражение **вычисляется в одно значение**; **некоторые** выражения дополнительно **меняют** состояние (побочный эффект); присваивание — пример такого выражения:

```javascript
clicks + 1              // вычисляется в число, но clicks НЕ меняется
clicks = clicks + 1     // тоже выражение, но записывает результат обратно в clicks
```

Сформулированное правило для урока: результат, **никуда не записанный**, переменную не меняет; `clicks = clicks + 1;` — вычисляет **и** записывает.

Дополнительно устранено расхождение терминов: заголовок «**Побочный эффект**» в Шаге 2 (который означал «сброс при перезагрузке») переименован в «**Наблюдение**», а фраза про конкатенацию строк перестала называть результат «побочным эффектом» — теперь это **термин** только для побочных эффектов в строгом смысле.

## 9. Остаточные риски

1. **Код ученика может быть непригоден для приведённого fallback** (например, обработчик навешен через `onclick` в атрибуте, счётчик живёт в модуле). Урок это **признаёт** и даёт один диагностический запрос к Codex; универсального решения без знания чужого кода не существует.
2. **Идентификатор `#theme-button` — соглашение урока.** Если у ученика на странице уже есть элемент с таким `id` (маловероятно), возникнет конфликт; текст предлагает «если у кнопки уже есть свой `id` — оставьте его и используйте его дальше», но автоматической проверки нет.
3. **«Строка из одного символа»** — формулировка верна для `"5"`, но для строк с escapes (например, `"\n"`) требуется оговорка о символе `\\n`; в рамках Урока 03 это не рассматривается и не требуется.
4. **Термин «побочный эффект»** введён в уроке; в дальнейших уроках (в т.ч. в Уроке 04 про условия) его нужно использовать терминологически последовательно.
5. **Отдельный счётчик очков** в упражнении Make дублирует вычисление (`points = clicks * 2` было бы проще). Это сделано намеренно — ради цели урока «два связанных значения»; для новичка это осознанное усложнение, а не оптимальный код.
6. **Проверка в настоящем браузере** не выполнена (см. §8) — поведение подтверждено шимом, но не реальным рендерингом.
7. **`git diff` для неотслеживаемых файлов** корректно описан, но ученик может по-прежнему искать правки через `git diff`; предупреждение в тексте присутствует, отдельного рабочего примера с `git add -N` намеренно **не** вводилось (Git получает прогрессивное лечение в отдельных уроках).
