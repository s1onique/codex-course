## 3. P1 — Исправление начального состояния Урока 04

### Дефект

Базовый код Урока 04 выполнял при инициализации:

```javascript
countDisplay.textContent = clicks;
message.textContent = 'Продолжайте!';
```

Сообщение при первом выводе было задано константой, а не вычислялось из текущего `clicks`. Урок 03 допускает начальное значение счётчика, отличное от нуля, поэтому при `clicks = 3` или `clicks = 10` страница до первого нажатия показывала неверное сообщение.

### Исправление

Сообщение при инициализации теперь вычисляется тем же правилом, что и после нажатия. Функции в Уроке 04 ещё не введены, поэтому условие намеренно продублировано в двух местах — это осознанный шаг, который Урок 05 устраняет:

```javascript
  countDisplay.textContent = clicks;

  if (message) {
    if (clicks >= 3) {
      message.textContent = 'Цель достигнута!';
    } else {
      message.textContent = 'Продолжайте!';
    }
  }
```

Урок 04 **не** вводит понятие функции: понятия Урока 05 не преждевременно выносятся в Урок 04.

## 4. P2 — Отсутствие `#message` больше не отключает счётчик

### Дефект

Базовый код возвращался молча, если не найден любой из трёх элементов:

```javascript
if (!themeButton || !countDisplay || !message) {
  return;
}
```

При отсутствии `#message` ранее рабочий счётчик полностью переставал работать, и в консоли не появлялось ничего — ученик видел «сломанную» страницу без диагностики.

### Исправление (наименьшее понятное изменение)

- Ранний `return` оставлен **только** для `#counter` и `#theme-button` — без них счётчик действительно запустить нельзя, и теперь это явно сообщается в консоли.
- Отсутствие `#message` больше не прекращает инициализацию: выводится понятная ошибка, счётчик продолжает работать, а обновление сообщения просто пропускается.
- Единственный путь инициализации сохранён — конкурирующих ветвей не появилось.
- Успешная инициализация не заявляется, если она не удалась: при отсутствии `#counter` или `#theme-button` выводится `console.error` и выполняется `return`.

```javascript
  if (!countDisplay || !themeButton) {
    console.error('Счётчик не запущен: не найдены элементы #counter или #theme-button.');
    return;
  }

  if (!message) {
    console.error('Элемент #message не найден. Сообщение о достижении цели не будет показано.');
  }
```

Асинхронная обработка ошибок не добавлялась; объяснение в уроке осталось на уровне новичка.

### Негативный контроль и подтверждение

```text
=== V2.4 Отсутствующий элемент #message ===
  PASS  P2: при отсутствии #message есть диагностика в console.error
  PASS  P2: счётчик продолжает работать при отсутствии #message
  PASS  P2: ровно одно увеличение за клик при отсутствии #message
  PASS  негативный контроль: старая реализация ломает счётчик без #message
```

Негативный контроль зафиксировал поведение старого кода: счётчик остался на `0` после клика и не выдал ни одной ошибки (`{ counter: '0', errors: 0 }`).

### 8.3 Проверка в браузере — попытка и её результат

Предпринята попытка выполнить документированный HTML **в настоящем браузере**:

```text
$ /Applications/Chromium.app/Contents/MacOS/Chromium --headless --dump-dom file://…
ERROR:chrome/browser/process_singleton_posix.cc:1043] Failed to create socket directory.
ERROR:chrome/app/chrome_main_delegate.cc:520] Failed to create a ProcessSingleton … Aborting now
```

Причина установлена точно, а не предположена: Chromium требует unix-сокет в каталоге данных приложения, а том, на котором лежит домашний каталог, не даёт ни создавать каталоги, ни привязывать сокеты:

```text
$ mkdir -p "$HOME/Library/Application Support/Chromium/CRTest"
mkdir: cannot create directory …: Operation not permitted

$ python3 -c "bind(AF_UNIX) в ~/Library/Application Support/Chromium"
SOCKET_FAIL: PermissionError [Errno 1] Operation not permitted
```

Проверены также `safaridriver` (требует интерактивной аутентификации администратора — в неинтерактивной сессии недоступен) и попытки с переопределением `HOME` и `--user-data-dir` (тот же сбой `ProcessSingleton`). Вывод: браузерная проверка в этой среде **невыполнима по причинам окружения**, а не по причинам кода.

Поэтому V5 выполнено на исполняемом JavaScript с **faithful DOM simulation**: моделируются `Element` (с приведением `textContent` к строке, как в настоящем DOM), `document.querySelector`/`getElementById`, `readyState`, `DOMContentLoaded`, `addEventListener`/`dispatchEvent`, а также разбор настоящего HTML. Это **не** доказательство визуального отображения — см. `NOT_EXECUTED` в разделе 11.

## 12. Остаточные риски

1. **Визуальное поведение не подтверждено в браузере.** DOM-симуляция точна для текста элементов, счётчика и вызовов, но не охватывает отрисовку, CSS и реальное переключение темы оформления. Риск: низкий (правки не затрагивают разметку и стили), но не нулевой. **Смягчение:** ученику предписана пошаговая проверка в браузере с таблицей ожидаемых значений.
2. **`console.error` может отвлечь.** Новичок может испугаться красной строки в консоли. **Смягчение:** текст ошибки объясняет причину и прямо говорит, что счётчик продолжает работать; Урок 04 объясняет, где смотреть консоль.
3. **Дублирование условия в Уроке 04.** Это намеренный компромисс: без функций правило приходится писать дважды, и ученик может забыть второе место. **Смягчение:** в тексте урока стоят явные указатели («Менять нужно **оба**»), а Урок 05 показывает, как это устраняется.
4. **Различие ученической реализации и канонической.** Ученик может иметь иное имя переменной, свой стиль или дополнительные счётчики. **Смягчение:** канонический вариант явно назван примером, а не образцом для копирования; инструкции говорят «сохраните свою рабочую логику».
5. **Разовое выполнение прогона.** Проверки выполнялись один раз на финальной версии файлов. **Смягчение:** проверки извлекают код из текстов уроков, поэтому любое последующее изменение текста потребует повторного прогона для сохранения доказательной базы.
6. **Мелкое исправление в `COURSE-OUTLINE.md` (строка 337).** Экранирование `\|` — изменение за пределами минимальной правки Урока 05, но оно внутри авторизованного пути и устраняет реальный дефект Markdown-таблицы, обнаруженный проверкой V6.4.
