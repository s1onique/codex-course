## 2. Исправления Урока 08

### 2.1 P1 — миграция необязательной четвёртой задачи

**Дефект.** Урок 06 добавлял четвёртую задачу через `tasks.push('Повторить материал');`. Урок 08 меняет элементы массива со строк на объекты. Ученик, правильно заменивший объявление массива, но оставивший старый вызов `push()`, получает смешанную коллекцию: **три объекта и одна строка**. `tasks.length` при этом возвращает `4`, и дефект не виден по длине.

**Исправление.** В разделе «Если у вас осталась четвёртая задача из Урока 06» добавлен **чек-лист миграции из 7 пунктов**: найти объявление `tasks`; найти остальные упоминания и вызовы `push()`; заменить массив строк на массив объектов; перевести оставшиеся `push()` на объектные; сохранить свою необязательную задачу; проверить «ровно один раз»; проверить наличие `title` и `done`.

Приведён канонический вид преобразования:

```javascript
// Было
tasks.push('Повторить материал');

// Стало
tasks.push({
  title: 'Повторить материал',
  done: false
});
```

Прямо названы две ловушки: **несовместимые типы** (строка в массиве объектов, `tasks[3].title === undefined`) и **дубль** (одна и та же задача и в литерале, и в `push()`). Сформулировано правило: четвёртая задача добавляется **одним** способом — либо в литерале, либо отдельным `push()`, но не обоими сразу. Формальная схема, библиотеки валидации и система типов **не** вводились.

Две поддерживаемые формы приведены явно:

- **Форма 1** — четыре объекта в литерале массива.
- **Форма 2** — три объекта плюс объектный `push()`.

Обе дают одинаковый результат: `tasks.length === 4`, номер четвёртой задачи `3`, есть `title` и `done`.

## 3. Урок 09

**Файл:** `LESSON-09.md` (490 строк), заголовок «Урок 09. Циклы: обрабатываем все задачи», оценка времени 45–75 минут, пререквизиты — Уроки 00–08.

**Цель.** Ученик может объяснить и использовать цикл `for...of` для обработки каждой задачи массива, предсказать число и порядок итераций и построить список задач из данных, а не из вручную записанных позиций.

**Главная модель урока.** «Цикл выполняет одну и ту же операцию для каждого элемента коллекции». Обязательные понятия раскрыты: повторение, тело цикла, текущий элемент, `for...of`, порядок обхода массива, ноль итераций для пустого массива. Отдельно разобрано, что `for...of` поставляет **значения**, а не индексы, — поэтому пишется `task.title`, а не `task[0].title`.

**Не введено** (согласно ограничению ACT): индексированный `for`, `for...in`, `while`/`do...while`, `break`/`continue`, `map`/`filter`/`reduce`/`forEach`, итераторы и генераторы, рекурсия, деструктуризация и spread, классы и прототипы, асинхронность, TypeScript, фреймворки и сборочные инструменты. Нет упоминаний алгоритмической сложности, протоколов итераторов и функциональных методов массива.

**Канонический пример.** Минимальный цикл из Урока 08:

```javascript
for (const task of tasks) {
  console.log(task.title);
}
```

**PRIMM.** Predict — пять предсказаний (число повторений и порядок для трёх и четырёх задач, влияние `done`, пустой массив) с таблицей для записи **до** запуска. Run — консольный пример и замена ручного показа. Investigate — шесть вопросов (почему обрабатывается каждый элемент, как работает `task.title`, почему три объекта дают три пункта, почему порядок совпадает с порядком массива, почему пустой массив даёт ноль пунктов, почему ручной показ не масштабировался). Modify — четвёртая задача в файле, перезагрузка, проверка четырёх пунктов, смена `done` у второй задачи, возврат к исходному состоянию. Make — необязательный, собственная задача-объект; явно помечен как **не** условие для Урока 10.

**Замена ручного показа.** HTML-блок «Ближайшая задача» заменяется целиком на:

```html
<section class="tasks-preview">
  <h2>Задачи</h2>
  <ul id="task-list"></ul>
  <p>Всего задач: <span id="task-count">—</span></p>
</section>
```

Указано, что это **замена**, а не второй блок, и что `#first-task`, `#second-task`, `#first-task-status` становятся ненужными; `#task-count` сохраняется. Функция `renderTaskList()` приведена ровно в каноническом виде из ACT. `createElement('li')` и `appendChild(item)` объяснены **только** как минимальные операции DOM, необходимые для построения списка, — не как отдельная тема. Названия вставляются через `textContent`; `innerHTML` не используется и запрещён явно. Вызов `renderTaskList()` — **один**, из существующего пути инициализации, после готовности DOM; новых обработчиков событий нет.

**Повторный показ.** Первое действие функции — `list.textContent = '';`, поэтому два вызова дают ровно по одному пункту на задачу. Ученику не требуется изучать согласование DOM или архитектуру управления состоянием.

**Сохранено.** Переключение темы, счётчик, сообщение о достижении цели, `achievementMessage()`, независимый `exampleTask`, необязательное упражнение `points`, законные дополнительные задачи. Устаревшие DOM-запросы удалены вместе с удалёнными элементами.

## 6. Наблюдения о когнитивной нагрузке

- **Счастливый путь — один.** «Три задачи, показанные руками → один цикл → показ всех задач». Один новый итерационный конструктор (`for...of`), одна каноническая реализация, никаких альтернативных синтаксисов на обязательном пути.
- **Новое понятие одно** — итерация. `createElement` и `appendChild` поданы как «два слова, которые нужны, чтобы построить список», без отдельного раздела и без ссылки на справочник DOM.
- **Проект и браузер прежние.** Тот же `practice/lesson-01/index.html`, тот же редактор, те же DevTools. Ничего не устанавливается.
- **Предпросмотр заменён, а не дополнен.** Старый ручной показ удаляется — на странице не появляется второй блок «Задачи».
- **Урок не раздут числом строк.** 490 строк против 615 у соседнего Урока 08 при вдвое большем числе разделов; причина — таблицы предсказаний и короткие абзацы, а не второй набор синтаксисов.
- **Различение данных и показа сохранено и усилено.** Урок прямо говорит: чтобы изменить, что показано, — меняйте данные; перезагрузка восстанавливает показ из данных.

## 9. Остаточные риски

1. **Имитация DOM не равна браузеру.** Тест проверяет логику `renderTaskList()` (число и текст `<li>`, очистка, диагностика), но не реальное поведение `document.createElement` / `appendChild` / `textContent` в браузере. Риск ограничен: используются только базовые и общеизвестные операции DOM, а расхождение проявилось бы как «список не появился», а не как тихая ошибка.
2. **Урок проверен статически, а не вживую.** Соблюдение шага «замените блок, а не добавьте второй» и отсутствие устаревших `#first-task`/`#second-task`/`#first-task-status` обеспечены инструкцией и статическими проверками; живой прогон ученика не измерялся.
3. **Разбор фрагментов урока привязан к заголовкам разделов.** Переименование заголовка в уроках (например, «### 1. Замените объявление `tasks`» или «##### Чек-лист миграции») приведёт к явной ошибке теста с понятным текстом — это намеренный компромисс между устойчивостью к сдвигу строк и однозначностью. При любом будущем переименовании заголовков тест надо обновить.
4. **Раздел «Что осталось на потом» Урока 08** по-прежнему обещает цикл в «следующем уроке» — теперь это действительно Урок 09; текст согласован по смыслу, отдельной правки формулировки не потребовалось.
5. **Две формы миграции** (литерал и `push()`) дают одинаковый результат, но ученик может выбрать любую; тест проверяет обе.
