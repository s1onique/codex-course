Урок объясняет различие прямо и без двусмысленности:

Ни одно из этих утверждений не противоречит другому, и оба подтверждены исполняемым кодом из текста урока (V2.1, V7.5).

### 8.3 Проверка в браузере — попытка и её результат

Предпринята попытка выполнить документированный HTML **в настоящем браузере** (Chromium 150.0.7871.46, установлен в `/Applications/Chromium.app`).

```text
$ /Applications/Chromium.app/Contents/MacOS/Chromium --headless --no-sandbox \
    --disable-gpu --user-data-dir=/tmp/cprof4 --dump-dom file:///tmp/t_chromium.html
[17644:89953289:1112/001659.678361:ERROR:chrome/browser/process_singleton_posix.cc:1043] Failed to create socket directory.
[17644:89953289:1112/001659.678557:ERROR:chrome/app/chrome_main_delegate.cc:520] Failed to create a ProcessSingleton for your profile directory. This means that running multiple instances would start multiple browser processes rather than opening a new window in the existing process. Aborting now to avoid profile corruption.
```

Причина установлена **точно**, а не предположена:

1. По исходному коду Chromium (`chrome/browser/process_singleton_posix.cc`, строка 1045) проверка вызывается так:
   `if (!socket_dir_.CreateUniqueTempDir(/*prefix=*/FILE_PATH_LITERAL(""))) { LOG(ERROR) << "Failed to create socket directory."; ... }`
2. `CreateUniqueTempDir` создаёт каталог во временной папке ОС.
3. На macOS `base::TempDir()` опирается на `NSTemporaryDirectory()`. Значение проверено напрямую через Foundation:
   `NSTemporaryDirectory = /var/folders/0g/mpt_55f524ndzxymkp20wjfc0000gn/T/`
4. В этом окружении песочница **запрещает создание подкаталогов** в этой папке. Проверено прямым `mkdir` из обычного процесса:
   `mkdir: cannot create directory '.../T/probe': Operation not permitted` (то же для `os.mkdir` из Python, и для `.chromium-probe-xyz`).
5. `TMPDIR` **перекрывается** песочницей на уровне процесса: и `TMPDIR=/tmp/ctmp2`, и `TMPDIR=/private/tmp/` не помогают — `NSTemporaryDirectory()` всё равно возвращает `/var/folders/.../T/`. `launchctl setenv TMPDIR` отклонён: «Not privileged to set domain environment».

Проверены и отброшены альтернативы: `--single-process`, `--headless=new`, `--no-startup-window`, `--remote-debugging-port` (CDP не поднялся), предварительное создание каталога `SingletonSocket` и его варианта-симлинка, профиль на локальном диске `/tmp` и на сетевом томе `/Volumes/UserData` — во всех случаях одна и та же ошибка. Playwright, Selenium, pyppeteer, Deno и другие движки в окружении отсутствуют.

**Вывод:** выполнение в настоящем браузере в этом окружении **невозможно** по причине, находящейся вне контроля агента. Проверки V2, V3 и V4 выполнены на **исполняемом JavaScript** и подтверждены **двумя независимыми способами**:

1. **Самодельная симуляция DOM** (Bun 1.3.14), 186 проверок, плюс тот же набор на Node.js v24.6.0 — результаты совпадают построчно.
2. **Настоящая DOM-реализация jsdom** (Node.js v24.6.0), 29 проверок: разметка **разбирается настоящим HTML-парсером**, `querySelector` работает по спецификации, события `click` и `DOMContentLoaded` — настоящие DOM-события.

Что по-прежнему **не** покрыто ни одной из этих проверок: **отрисовка**, CSS, реальное переключение темы оформления, вёрстка, зрительное восприятие. Значения, полученные в симуляции и в jsdom, **не являются доказательством визуального отображения**.

## 12. Остаточные риски

1. **Визуальное поведение не подтверждено в браузере.** DOM-симуляция и jsdom точны для текста элементов, счётчика, числа вызовов и разбора разметки, но не охватывают отрисовку, CSS и реальное переключение темы. Риск: **низкий** (правки не затрагивают разметку и стили), но не нулевой. **Смягчение:** ученику предписана пошаговая проверка в браузере с таблицами ожидаемых значений.
2. **Совместимость с ученическими реализациями.** Проверены каноническая реализация и представительный вариант с `points`. **Совместимость со всеми возможными ученическими реализациями не установлена и не заявляется.** **Смягчение:** урок называет канонический пример примером, а не образцом; инструкции говорят «сохраните свою рабочую логику».
3. **Незаметная поломка при копировании кода.** Новичок может вставить `tasks.push(...)` **в консоль**, а не в файл, и увидеть старое число на странице. **Смягчение:** это объяснено отдельным подразделом «Почему число на странице может остаться старым» и дана процедура восстановления состояния.
4. **Ошибка «начинаем с единицы».** Главная содержательная ловушка урока. **Смягчение:** предсказание заранее, явное правило «последний номер = `length` − 1», таблица с `tasks[0]` и `tasks[1]` и отдельный негативный контроль NC-1.
5. **Разовое выполнение прогона.** Проверки выполнялись один раз на финальной версии файлов. **Смягчение:** проверки извлекают код из текстов уроков, поэтому любое последующее изменение текста потребует повторного прогона для сохранения доказательной базы.
6. **Пустые строки в конце файлов.** Дефект, который этот ACT чинит, вернётся, если кто-то снова будет дописывать файл с лишним переводом строки. **Смягчение:** `git diff --check` включён в обязательные проверки ACT, а V1.5 проверяет завершающие переводы строки явно.
