### 8.1a. Как получить идентификаторы финального коммита

Коммит, содержащий настоящий отчёт, не может записать собственный SHA внутри себя: любая правка отчёта меняет хеш коммита, и записанное значение немедленно устаревает. Поэтому идентификаторы приведены не внутри файла, а **проверяемым способом**:

```powershell
git rev-parse HEAD
git rev-parse HEAD^{tree}
git show --stat --oneline HEAD
```

На момент передачи ACT наблюдались следующие значения (проверено исполнением команд):

| Параметр | Значение |
|---|---|
| HEAD | `df453de68977a306b129cef9d6e1979c3dca2ea7` |
| Tree | `1fc083e8ffe9b40acd7821eabd31e83d66782a5e` |
| Родитель (базовый HEAD) | `991033ed101dc9977a764d8e4d62cdf52671f768` |

**Примечание об изменении значения.** Приведённый выше SHA финального коммита был получен до последней правки этого раздела отчёта, поэтому он на один коммит отличается от значения, которое вернёт `git rev-parse HEAD` в текущем состоянии репозитория. Итоговое значение указано в **сообщении коммита** и воспроизводится указанной командой. Все прочие идентификаторы (базовый HEAD, базовое дерево, origin, путь репозитория) устойчивы и проверены.
