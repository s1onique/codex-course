# Урок 05. Функции и параметры

**Время:** 45–75 минут (оценка)
**Уровень:** начинающий
**Пререквизиты:** пройдены [Урок 00](LESSON-00.md), [Урок 01](LESSON-01.md), [Урок 02](LESSON-02.md), [Урок 03](LESSON-03.md) и [Урок 04](LESSON-04.md). У вас есть работающий счётчик с сообщением «Цель достигнута!» и исходная кнопка «Поменять оформление».
**Результат:** вы можете вынести повторяющийся расчёт в отдельную функцию, передать в неё значение, получить результат и лично убедиться, что страница ведёт себя точно так же, как до переделки.

> **Главная идея урока.** Функция — это **переиспользуемое поведение с понятным именем, входом и результатом**. Сегодня вы возьмёте расчёт сообщения, который в Уроке 04 был написан дважды, и превратите его в одну функцию. Страница при этом будет выглядеть и работать **точно так же** — изменится только внутреннее устройство.

---

## Чему научимся

После урока вы сможете:

1. Объяснить, зачем нужен `function`, и назвать отличие функции от обычного куска кода.
2. Написать функцию с параметром и получить её результат через `return`.
3. Отличить **параметр** (имя входа внутри функции) от **аргумента** (значение, которое вы передали при вызове).
4. Вызвать одну и ту же функцию с разными аргументами и получить разные результаты.
5. Понять, что функция, которая считает, и код, который меняет страницу, — это разные вещи.
6. Переписать повторяющийся расчёт в функцию и не сломать поведение страницы.
7. Проверить, что после переделки всё работает как раньше.

Ни нового проекта, ни библиотек, ни сервера, ни Node.js, ни стрелочных функций, ни замыканий, ни рекурсии, ни классов, ни TypeScript и новых инструментов. Работаем в том же `practice/lesson-01/index.html`, в том же редакторе и браузере.

### 2. Замените оба места на вызов функции

**Место первое** — при первом выводе (то, что в Уроке 04 было просто `message.textContent = 'Продолжайте!';`):

**Место второе** — внутри обработчика нажатия:

```javascript
themeButton.addEventListener('click', function () {
  clicks = clicks + 1;
  countDisplay.textContent = clicks;

  if (!message) {
    return;

```

Теперь условие `clicks >= 3` есть **только в одном месте** — внутри функции.


### 3. Конечный обрабатываемый кусок

Так это должно выглядеть целиком:

```javascript
let clicks = 0;

function achievementMessage(count) {
  if (count >= 3) {
    return 'Цель достигнута!';
  } else {
    return 'Продолжайте!';
  }
}

function startCounter() {
  const countDisplay = document.querySelector('#counter');
  const themeButton = document.querySelector('#theme-button');
  const message = document.querySelector('#message');

  if (!countDisplay || !themeButton) {
    console.error('Счётчик не запущен: не найдены элементы #counter или #theme-button.');
    return;
  }

  if (!message) {
    console.error('Элемент #message не найден. Сообщение о достижении цели не будет показано.');
  }

  countDisplay.textContent = clicks;

  if (message) {
    message.textContent = achievementMessage(clicks);
  }

  themeButton.addEventListener('click', function () {
    clicks = clicks + 1;
    countDisplay.textContent = clicks;

    if (!message) {
      return;
    }

    message.textContent = achievementMessage(clicks);
  });
}

if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', startCounter);
} else {
  startCounter();
}
```

Это **канонический вариант**. Если ваш счётчик устроен иначе, **сохраните свою рабочую логику** и замените только два куска с `if`/`else` на вызов `achievementMessage(clicks)`. Ничего больше не трогайте: ваши собственные изменения, дополнительные счётчики и оформление остаются на месте.

> **Если у вас есть упражнение `points` из Урока 03** — перенесите его вместе с вашим кодом и не затирайте. Функция `achievementMessage()` ничего не ломает в других частях файла.

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Где функция начинается и заканчивается

Посмотрите на `achievementMessage` в своём файле:

```javascript
function achievementMessage(count) {
  if (count >= 3) {
    return 'Цель достигнута!';
  } else {
    return 'Продолжайте!';
  }
}
```

- `function` — слово «здесь определяется функция»;
- `achievementMessage` — **имя** функции. Имя вы выбираете сами, и оно должно отвечать на вопрос «что она делает?»;
- `(count)` — скобки с входными данными;
- `{ ... }` — тело функции: код, который выполнится при вызове;
- закрывающая `}` — конец функции.

Тело функции — это отдельный кусок кода. Он **не выполняется сам по себе**, пока функцию не позовут.

### Параметр и аргумент — два разных слова

Посмотрите на одну строку объявления и на один вызов:

```javascript
function achievementMessage(count) {
  // count — это параметр
}

achievementMessage(3); // 3 — это аргумент
```

- **Параметр** `count` — это *имя* входа внутри функции. Оно нужно функции, чтобы знать, с каким значением работать. Само по себе слово `count` ничего не значит.
- **Аргумент** `3` — это *значение*, которое вы передали в момент вызова. Именно оно попадёт в `count` на время этого вызова.

Коротко: **параметр — имя, аргумент — значение.**

Поэтому, когда мы пишем `achievementMessage(clicks)`, мы говорим: «посчитай, используя текущее значение `clicks`».

### Что делает `return`

```javascript
if (count >= 3) {
  return 'Цель достигнута!';
} else {
  return 'Продолжайте!';
}
```

`return` делает две вещи:

1. **Отдаёт результат** вызывающему коду. Вот эта строка — то, что покажет консоль и что попадёт в `message.textContent`.
2. **Завершает эту работу функции.** Код ниже `return` в этой же функции уже не выполнится.

Функция, в которой нет `return`, ничего не отдаёт вызывающему коду: результат будет `undefined`.

### Считает — или меняет страницу?

Это самое важное различие в уроке. Сравните две строки:

```javascript
message.textContent = achievementMessage(clicks);
```

Здесь происходит **два разных дела**:

| Что | Код | Что делает |
|---|---|---|
| **Считает** | `achievementMessage(clicks)` | Вычисляет строку и **возвращает** её. Никаких элементов страницы не трогает. |
| **Показывает** | `message.textContent = ...` | Присваивает полученную строку элементу на странице. Вот здесь страница меняется. |

Проверить это легко. Вызовите функцию в консоли — и посмотрите на страницу:

```javascript
achievementMessage(0)
```

Консоль покажет `Продолжайте!`, но **сообщение на странице не изменится**. Функция ничего не знает про `#message` — она не обращается к странице вообще.

А вот эта строка страницу меняет:

```javascript
message.textContent = achievementMessage(clicks);
```

**Вывод:** функция `achievementMessage()` — это «калькулятор сообщения». А `message.textContent = ...` — это «показать результат на странице». Одно без другого не работает: калькулятор без показа никто не увидит, а показать нечего.

### Знакомое сравнение: `startCounter()`

Вы уже пользовались функцией — но без параметров:

```javascript
startCounter();
```

У `startCounter()` нет параметров: она ничего не принимает и ничего не возвращает, а просто делает своё дело (находит элементы, навешивает обработчик, выводит первое значение).

Сравните:

| | `startCounter()` | `achievementMessage(clicks)` |
|---|---|---|
| Параметры | нет | один: `count` |
| Что отдаёт | ничего (`undefined`) | строку с сообщением |
| Зачем зовётся | один раз при старте | много раз: при первом выводе и после каждого нажатия |

### Почему функцию можно вызывать много раз

Функция не «выполняется один раз и умирает». Каждый вызов — это отдельный запуск её тела:

1. При первом выводе: `achievementMessage(clicks)` с текущим `clicks`.
2. После первого нажатия: снова `achievementMessage(clicks)`, но `clicks` уже другой.
3. После второго нажатия: снова, с новым `clicks`.

Один и тот же код — разные результаты, потому что разные **аргументы**. Именно поэтому функция «вычисляет», а не «показывает»: результат зависит только от того, что вы передали.

> **Совет.** Когда будете читать свой код, ищите глазами `function` — и вы увидите, где какое поведение живёт. Это дешевле, чем искать «тот кусок, где вроде бы считается сообщение».

Параметр — имя входа внутри функции (`count`), аргумент — переданное значение (`3` в `achievementMessage(3)`). `return` отдаёт результат вызывающему коду и завершает работу функции; без него результат будет `undefined`. `achievementMessage(3)` вернёт `Цель достигнута!`, а `achievementMessage(2)` — `Продолжайте!`. Функцию можно зоввать много раз, потому что её результат зависит только от аргумента, а не от «однократного запуска». `achievementMessage(clicks)` только вычисляет строку; `message.textContent = achievementMessage(clicks)` дополнительно записывает её в элемент — вот эта строка меняет страницу. Поэтому после вызова `achievementMessage(0)` в консоли страница не изменится: функция не обращается к DOM. `startCounter()` не имеет параметров, ничего не возвращает и вызывается один раз при старте; `achievementMessage(clicks)` принимает значение, возвращает строку и вызывается многократно. В коде изменилось внутреннее устройство: условие `>= 3` теперь написано один раз внутри функции, а на его месте стоят вызовы; наблюдаемое поведение — число нажатий, сообщение, работа кнопки оформления — осталось прежним.

---

## Это не «новая программа», а переделка старой

Важно, что именно вы сделали. Вы **не добавили** функцию к готовой программе — вы **переписали** её внутреннее устройство, не изменив того, что видно пользователю. В программировании такое называют **рефакторингом**.

Правило простое:

> **Те же входные и то же состояние → те же ожидаемые наблюдаемые результаты, хотя внутри программа устроена иначе.**

«Наблюдаемый результат» — это то, что человек видит на странице: число нажатий, текст сообщения, работа кнопки оформления. Внутреннее устройство — то, как код это вычисляет.

Поэтому после переделки обязательно проверьте, что ничего не сломалось:

| Что проверить | Как | Ожидаемо |
|---|---|---|
| Число нажатий | Нажмите кнопку 3 раза | `3` |
| Сообщение при первом выводе | Обновите страницу | `Продолжайте!` |
| Сообщение после 3-го нажатия | Нажмите 3 раза | `Цель достигнута!` |
| Сообщение после 4-го нажатия | Нажмите 4 раза | `Цель достигнута!` |
| Одно нажатие — одно увеличение | Считайте число после каждого клика | `1`, `2`, `3`, … |
| Кнопка оформления | Нажмите её | Тема меняется как раньше |
| Ваши собственные доработки | Проверьте то, что добавляли раньше | Работает как раньше |

Если что-то сломалось — ищите, не забыли ли вы заменить **оба** прежних места на вызов функции. Сравните свой файл с каноническим вариантом из Шага 2 шага Run.

> **Ваш файл и канонический вариант — это разные вещи.** Канонический вариант показывает, как это выглядит у «эталонного» ученика. Ваш файл может отличаться: у вас может быть другое имя переменной, свой стиль, дополнительный счётчик `points` или свой оформление. Это нормально и не считается ошибкой — ошибкой будет, только если поведение изменилось.

## Критерий завершения урока

Урок пройден, если вы **самостоятельно**:

1. Объясняете, зачем нужна функция.
2. Пишете функцию с параметром и получаете результат через `return`.
3. Различаете параметр и аргумент и приводите пример из своего кода.
4. Вызываете одну функцию с разными аргументами и получаете разные результаты.
5. Объясняете, что функция считает, а `textContent` — показывает.
6. Объясняете, почему одну и ту же функцию можно вызывать многократно.
7. Вынесли расчёт сообщения в `achievementMessage()` и заменили оба прежних места на вызов.
8. Проверили, что после переделки страница работает **как раньше**: число, сообщение, кнопка оформления.

Шаг Make и упражнение `points` из Урока 03 — **необязательные**.

Если что-то не получилось, запишите это прямо. **Не выдавайте ожидаемый результат за фактический** — это главный навык всего курса.
