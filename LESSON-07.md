## Шаг 1. Predict — сначала предсказываем (10 минут)

### Что мы собираемся сделать

У задачи есть **два** признака: как она называется и выполнена она или нет. В Уроке 06 мы хранили только названия — по одному значению на задачу. Если бы нам понадобилось ещё и «выполнена или нет», пришлось бы заводить **две** переменные на каждую задачу:

```javascript
const taskTitle = 'Составить план';
const taskDone = false;
```

А если задач пять? Десять? Имена быстро перестанут совпадать, и в какой-то момент вы перепутаете, где чьё состояние. Нужен **один** ящик, в котором лежат **все признаки одной задачи** и у каждого признака есть **имя**. Такой ящик в JavaScript называется **объект**.

### Канонический пример

```javascript
const exampleTask = {
  title: 'Составить план',
  done: false
};
```

Здесь:

- `exampleTask` — имя переменной, «ящик»;
- `{ ... }` — **литерал объекта**: запись, в которой перечислены свойства;
- `title` и `done` — **имена свойств**;
- `'Составить план'` и `false` — **значения** свойств;
- `:` — разделитель между именем и значением;
- `,` — разделитель между свойствами.

### Запишите предсказания ДО запуска

Это главное упражнение урока. **Прежде чем запускать код**, запишите в таблицу, что произойдёт:

```javascript
const exampleTask = {
  title: 'Составить план',
  done: false
};

exampleTask.title
exampleTask.done
exampleTask.done = true
exampleTask.done
```

| Выражение | Ваше предсказание |
|---|---|
| `exampleTask.title` | |
| `exampleTask.done` | |
| `exampleTask.done = true` | |
| `exampleTask.done` (после предыдущей строки) | |

**Не переходите к следующему шагу, пока таблица не заполнена.**

> **Подсказка (только если совсем не получается).** `exampleTask.title` — это чтение: программа показывает, что лежит в свойстве `title`. Значение `exampleTask.done` сначала `false` — так оно записано в объекте. Строка `exampleTask.done = true` — это **присваивание**: она меняет само свойство, поэтому следующее чтение даст `true`.

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Что такое объект

**Объект** — это набор **именованных свойств**, описывающих одну сущность. В нашем случае сущность одна: **пример задачи**.

| Что | Как называется | Пример |
|---|---|---|
| `exampleTask` | **переменная** — «ящик» с именем | `const exampleTask = { ... };` |
| `title`, `done` | **свойства** — именованные признаки | `exampleTask.title` |
| `'Составить план'`, `false` | **значения** свойств | `exampleTask.done` |

Ключевое слово «**именованные**»: у каждого свойства есть **имя**, по которому к нему можно обратиться.

### Что значат фигурные скобки

В **объектном литерале** `{ ... }` стоят свойства, перечисленные через запятую. Каждое свойство записывается как **имя**, затем `:` (двоеточие), затем **значение**:

```javascript
const exampleTask = {
  title: 'Составить план',
  done: false
};
```

Двоеточие `:` здесь читается как «**свойство `title` равно `Составить план`**».

> **Не путайте с блоком кода `{ ... }`.** В фигурных скобках после `=` мы пишем **список свойств**, а не команды. Сравните с блоком `if` из Урока 04, где в скобках стояли **команды**.

### Почему у свойств есть имена

Без имён пришлось бы угадывать позицию, как в массиве: «третье значение — это что?». Имя отвечает на вопрос прямо: `done` — это **состояние**, `title` — это **название**. Перепутать их невозможно.

### Почему `title` и `done` могут иметь разные типы значений

Это **нормально**. Свойство — это «ячейка с подписью», а в ячейке может лежать что угодно: строка, число, логическое значение.

| Свойство | Значение | Тип | Что это |
|---|---|---|---|
| `title` | `'Составить план'` | строка | название задачи |
| `done` | `false` | логическое значение (`true` / `false`) | выполнена или нет |

Именно поэтому `done` сравнительно удобно превращать в текст через `if`/`else`: у логического значения всего два состояния, значит, и веток две.

### Почему точечная запись

Чтобы прочитать свойство, пишут **имя переменной, точку и имя свойства**:

```javascript
exampleTask.title   // 'Составить план'
exampleTask.done    // false
```

Это называется **точечная запись** (dot notation). Смысл такой: «у объекта `exampleTask` возьми свойство `title`».

### Почему `const` не мешает менять свойство

Вот это нужно понять до конца урока.

Мы объявили объект так:

```javascript
const exampleTask = {
  title: 'Составить план',
  done: false
};
```

`const` означает: **саму переменную нельзя переприсвоить**. Нельзя сделать `exampleTask = { ... }` — это ошибка.

Но `const` **не означает**, что содержимое объекта неизменно. Объект — это ящик, а `const` говорит только: «этот ящик всегда будет тем же ящиком». Что лежит **внутри** ящика — можно менять.

```javascript
exampleTask.done = true;   // ок: содержимое изменить можно
```

> **Кратко:** `const` защищает **имя** ящика, а не его содержимое. В Уроке 06 мы выяснили то же самое про массив.

### Чтение и присваивание — это разные вещи

Сравните два выражения:

```javascript
exampleTask.done        // ЧТЕНИЕ: спрашиваем «какое сейчас значение?»
exampleTask.done = true // ПРИСВАИВАНИЕ: говорим «пусть теперь будет true»
```

- **Чтение** возвращает значение. Оно ничего не меняет.
- **Присваивание** меняет свойство. Само выражение-присваивание тоже имеет значение (новое), но для нас важно другое: после него состояние объекта **другое**.

Именно поэтому в таблице предсказаний строка `exampleTask.done = true` — это не «что вернёт выражение», а «что оно сделает».

### Где `exampleTask`, а где `tasks` — и почему это разные вещи

В вашем файле сейчас два разных ящика:

```javascript
const tasks = [
  'Прочитать главу',
  'Сделать упражнение',
  'Проверить результат'
];

const exampleTask = {
  title: 'Составить план',
  done: false
};
```

| | `tasks` | `exampleTask` |
|---|---|---|
| Что это | **массив** | **объект** |
| Что внутри | три **значения** по порядку | два **именованных свойства** |
| Как достать | по **номеру**: `tasks[0]` | по **имени**: `exampleTask.title` |
| Сколько всего | `tasks.length` → `3` | сколько свойств — видно по коду |

**Главное различие:** массив — это **несколько значений в упорядоченной коллекции** (достаёшь по номеру), объект — это **несколько связанных свойств одной сущности** (достаёшь по имени).

**Важно:** `exampleTask` **не входит** в `tasks` и никак с ним не связан. Измените `exampleTask.done` — массив `tasks` не изменится. Измените `tasks` — у `exampleTask` ничего не поменяется. Это **два независимых примера**: сейчас мы учимся самому объекту, а связать их в один трекер задач будем в следующем уроке.

> **Не путайте объект с массивом.** Объект — это не «массив без порядка». Это другая вещь: у массива элементы **перечисляются по номерам**, у объекта свойства **называются по именам**. Сравните `tasks[0]` и `exampleTask.title`.

### Почему в консоли и в файле получается разный результат

Это ровно то, что мы разобрали в Уроке 06, — только теперь для объекта.

Если вы выполнили `exampleTask.done = true` **только в консоли**, объект в памяти страницы действительно изменился: `exampleTask.done` вернёт `true`. Но **текст на странице останется прежним** — `Не выполнена`. Потому что текст в `#example-task-status` был записан **один раз, при загрузке страницы**, и сам по себе он не переписывается.

Если вы изменили **файл** (поставили `done: true` в самом объекте или добавили строку присваивания в файл), то при перезагрузке страница выполняет код заново, объект создаётся уже в новом состоянии, и при загрузке записывается `Выполнена`.

| Ситуация | `exampleTask.done` | Что показано в `#example-task-status` |
|---|---|---|
| Страница только что загрузилась | `false` | `Не выполнена` |
| Присваивание выполнено **только в консоли** | `true` | `Не выполнена` |
| Страница перезагружена, **файл не изменён** | `false` | `Не выполнена` |
| Присваивание добавлено **в файл**, страница перезагружена | `true` | `Выполнена` |

Обратите внимание на третью строку: консольное изменение **не пережило перезагрузку**. Файл остался прежним — значит, и объект создался прежним.

> **Проверка на «всё живое».** Нажмите кнопку счётчика: он должен работать как раньше, сообщение должно меняться, кнопка оформления — переключать тему. Новая часть урока не должна была ничего сломать.

### Верните исходное состояние

Удалите строку `exampleTask.done = true;` из файла (или верните `done: false` в объекте), сохраните и обновите страницу. Состояние снова станет `Не выполнена`.

Это хорошая проверка: значит, текст на странице действительно вычисляется из свойства объекта, а не написан руками.

> **Перед тем как закончить урок, верните исходное состояние** — иначе следующий урок начнётся с уже изменёнными данными.

### Что `const` запрещает, а что — нет

Этот пункт важнее, чем кажется, потому что в Уроке 06 мы уже говорили про `const` — но про **массив**.

| Что вы хотите сделать | Массив | Объект |
|---|---|---|
| Переприсвоить саму переменную (`tasks = [...]`, `exampleTask = {...}`) | **нельзя** — ошибка | **нельзя** — ошибка |
| Изменить **элемент** массива (`tasks[0] = '...'`) | **можно** | — |
| Изменить **свойство** объекта (`exampleTask.done = true`) | — | **можно** |

Читается это так: `const` запрещает **переприсвоить имя** — то есть связать с именем `tasks` или `exampleTask` что-то другое. Но `const` **не** делает содержимое неизменным: ни элементы массива, ни свойства объекта он не замораживает.

> **Кратко:** `const` защищает **имя** ящика, а не его содержимое. Это работает **одинаково** для массива и для объекта. Ни массив, ни объект не становятся «неизменяемыми» только потому, что объявлены через `const`.

**Что осталось на потом.** Полноценный трекер задач — это **массив объектов**: несколько задач, у каждой свой заголовок и своё состояние. Связать то, что вы сегодня научились, в одну коллекцию мы будем в следующем уроке. Здесь мы сделали **первый шаг к объектам**: научились описывать одну задачу именованными свойствами.
