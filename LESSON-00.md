# Урок 0. Устанавливаем Git на Windows 10 и подключаем свой репозиторий

**Время:** 25–40 минут  
**Уровень:** начинающий  
**Нужно:** Windows 10, доступ в интернет, существующий аккаунт и репозиторий на GitHub, установленный Codex.  
**Результат:** команда `git` работает на компьютере, учебный репозиторий скопирован с GitHub, Codex может открыть его локальную папку.

> **О Windows 10 (актуально на 2026-11-11).** Обычная поддержка Windows 10 версии 22H2 завершилась 2025-10-14. Git на ней ещё можно использовать, но следует отдельно позаботиться об актуальных обновлениях безопасности (при наличии права на ESU) либо переходе на поддерживаемую ОС. Этот урок не меняет настройки Windows и не требует обновления системы.

## Чему научимся

После урока вы сможете:

1. Отличать Git, GitHub и GitHub Desktop друг от друга.
2. Установить **Git for Windows** и убедиться, что он запускается.
3. Настроить имя и адрес автора коммитов.
4. Скопировать **свой** GitHub-репозиторий на компьютер через HTTPS.
5. Открыть локальную папку проекта в Codex и безопасно проверить состояние Git.

## Три названия, которые важно различать

| Название | Что это |
|---|---|
| **Git** | Программа для хранения истории изменений файлов проекта. |
| **GitHub** | Сайт, на котором хранится удалённая копия репозитория. |
| **GitHub Desktop** | Необязательное графическое приложение для работы с Git и GitHub без командной строки. |

**Клонировать (clone)** — значит скачать репозиторий с GitHub на компьютер, сохранив связь с удалённой копией. Это **не** означает создать репозиторий в своём GitHub-аккаунте и **не** означает сделать fork.

У нас два разных репозитория:

- **[Курс `s1onique/codex-course`](https://github.com/s1onique/codex-course)** — здесь находятся уроки. Его достаточно читать в браузере; изменять его не нужно.
- **Ваш собственный GitHub-репозиторий** — здесь вы будете выполнять задания. Именно его нужно открыть в Codex.

## Шаг 1. Проверяем тип Windows (2 минуты)

Откройте **Пуск → Параметры → Система → О системе (About)** и найдите строку «Тип системы».

- Если указано **64-разрядная операционная система, процессор x64** — скачайте вариант Git for Windows **x64**.
- Если указано **ARM64** — на странице загрузки выберите вариант **ARM64**.
- Если указано **32-разрядная операционная система** — остановитесь и уточните вариант установки у преподавателя: текущие стандартные сборки и современные вспомогательные программы рассчитаны на 64-разрядные системы.

## Шаг 2. Устанавливаем Git for Windows (5–10 минут)

1. Откройте официальный сайт: **https://git-scm.com/install/windows**.
2. Скачайте установщик **Git for Windows** для своей архитектуры (обычно x64). Не скачивайте его со случайных сайтов.
3. Запустите загруженный `.exe` и пройдите мастер установки.
4. На большинстве экранов оставьте настройки по умолчанию. Обратите внимание на две настройки:
   - **Adjusting your PATH environment:** выберите или оставьте **Git from the command line and also from 3rd-party software**, чтобы `git` был доступен из PowerShell и другим программам.
   - **Credential helper:** выберите или оставьте **Git Credential Manager** — он поможет войти в GitHub через браузер вместо ручного ввода токена.
5. Завершите установку. Если PowerShell был открыт, **закройте его и откройте заново**.

> Для этого урока **не нужны SSH-ключи**, персональные токены GitHub, права администратора для команд Git, WSL или установка Linux.

### Проверка установки

Откройте **Пуск**, введите **PowerShell** и запустите **Windows PowerShell** (обычный, не от имени администратора).

Введите:

```powershell
git --version
```

**Ожидаемый результат:** строка, начинающаяся с `git version`, например `git version 2.xx.x.windows.x`. Номер версии может отличаться — это нормально.

Если вместо этого появляется сообщение `git is not recognized` / «Имя git не распознано», проверьте, что открыли **новое** окно PowerShell. Если ошибка сохраняется, переустановите Git for Windows с настройкой PATH из шага 2. Не изменяйте системный PATH вручную наугад.

## Шаг 3. Указываем автора изменений (3–5 минут)

Git сохраняет автора каждого коммита. Нужно один раз настроить имя и email.

В PowerShell выполните **с вашими значениями**:

```powershell
git config --global user.name "Ваше имя или ник"
git config --global user.email "ВАШ_EMAIL_НА_GITHUB"
```

Email должен принадлежать вашему GitHub-аккаунту. Если не хотите показывать личный адрес в истории публичных репозиториев, используйте **ваш точный GitHub `noreply`-адрес**, который можно найти в настройках GitHub **Settings → Emails**. Не копируйте `noreply`-адрес другого человека.

Проверьте:

```powershell
git config --global user.name
git config --global user.email
```

**Ожидаемый результат:** имя и email, которые вы только что указали.

## Шаг 4. Клонируем СВОЙ репозиторий (5–10 минут)

1. Откройте в браузере **свой** существующий репозиторий на GitHub.
2. Нажмите зелёную кнопку **Code**, выберите **HTTPS** и скопируйте адрес. Он выглядит примерно так: `https://github.com/USERNAME/REPOSITORY.git`.
3. В PowerShell создайте отдельную папку для проектов и перейдите в неё:

```powershell
New-Item -ItemType Directory -Force -Path "$HOME\Projects"
Set-Location "$HOME\Projects"
```

4. Клонируйте репозиторий, подставив **скопированный адрес вместо примера**:

```powershell
git clone https://github.com/USERNAME/REPOSITORY.git
```

5. Перейдите в появившуюся папку (замените `REPOSITORY` на настоящее имя):

```powershell
Set-Location .\REPOSITORY
```

6. Проверьте состояние проекта:

```powershell
git status --short --branch
git remote -v
```

**Ожидаемый результат:** `git status` показывает название ветки, например `## main...origin/main`, и не показывает неожиданных изменений. Команда `git remote -v` показывает адрес **вашего** репозитория на GitHub.

Если имя ветки не `main`, это **не ошибка** — используйте ту ветку, которая существует в вашем проекте.

**Если репозиторий уже скачан на компьютер:** не клонируйте его повторно. Откройте существующую папку и выполните две проверочные команды из пункта 6.

### Как происходит вход в GitHub

Для публичного репозитория вход обычно не нужен. Если репозиторий приватный, Git Credential Manager может предложить авторизоваться в **браузере**. Войдите в **свой** GitHub-аккаунт и подтвердите запрос доступа, внимательно проверив его источник.

**Не вводите пароль от GitHub вместо токена в терминал и не отправляйте никому токены или пароли.** Для этого упражнения не нужно создавать персональный токен вручную.

## Шаг 5. Открываем проект в Codex (5 минут)

Если Codex работает с локальными папками, выберите **папку вашего репозитория**, например:

```text
C:\Users\<ваш-пользователь>\Projects\REPOSITORY
```

Если вы пользуетесь **Codex CLI**, его можно запустить в том же PowerShell, где уже открыта папка репозитория:

```powershell
codex
```

При установленном Codex CLI откроется его интерфейс. Если пользуетесь приложением Codex, откройте папку проекта в нём; устанавливать CLI специально для этого урока не нужно.

Скопируйте в Codex **только запрос**, не включая маркеры блока:

```text
Проверь мой текущий проект, но ничего не изменяй.
1. Скажи, в какой папке проекта ты работаешь.
2. Определи текущую ветку Git.
3. Выполни git status и сообщи, есть ли изменения.
4. Покажи адрес origin (не раскрывай секреты, если они есть).
Не меняй файлы, не создавай коммиты и ничего не отправляй на GitHub.
Если не можешь выполнить команду, так и скажи.
```

**Ожидаемый результат:** Codex показывает папку именно **вашего** репозитория, называет существующую ветку и описывает реальное состояние Git. Если ему не удалось выполнить команды, это ещё не успешная проверка — разберитесь с доступом к локальному проекту перед уроком 1.

## Необязательно: графический GitHub Desktop

Если команды кажутся неудобными, можно также установить **GitHub Desktop**: **https://desktop.github.com/**. На Windows 10 он требует **64-разрядную** систему.

1. Установите программу с официального сайта.
2. Нажмите **Sign in to GitHub.com** и авторизуйтесь через браузер.
3. Проверьте имя и email в **File → Options → Git**.
4. Для уже клонированного проекта выберите **File → Add Local Repository** и укажите его папку. Если ещё не клонировали проект, выберите **File → Clone Repository** и найдите свой репозиторий в списке или на вкладке **URL**.
5. В будущем вкладка **Changes** покажет изменённые файлы, **History** — коммиты, а **Push origin** отправит ваши коммиты на GitHub.

**Важно:** GitHub Desktop удобен для визуальной работы, но установка *только* GitHub Desktop **не заменяет** установку Git for Windows, если вы хотите запускать команду `git` отдельно в PowerShell или использовать её в инструментах Codex.

## Если что-то не получилось

| Проблема | Что проверить |
|---|---|
| `git` не найден | Перезапустите PowerShell, проверьте установку и настройку PATH. |
| `Repository not found` | Правильность HTTPS-адреса, свой аккаунт и права доступа к приватному репозиторию. |
| `Authentication failed` | Вход через Git Credential Manager; не подставляйте пароль от GitHub в команду. |
| `destination path ... already exists` | Папка уже есть. Проверьте, не клонирован ли проект ранее. Не удаляйте её автоматически. |
| В Codex виден не тот проект | Проверьте, какую **локальную папку** открыли. |
| Есть незнакомые изменения в `git status` | Не сбрасывайте и не удаляйте их. Сначала выясните, откуда они. |

## Самостоятельная проверка

- [ ] Команда `git --version` работает в новом PowerShell.
- [ ] Имя и email автора Git настроены правильно.
- [ ] Мой собственный репозиторий есть в папке `Projects` (или в другой известной мне папке).
- [ ] `git remote -v` указывает на **мой** GitHub-репозиторий.
- [ ] Codex открыл **эту же папку**, а не репозиторий курса.
- [ ] Я понимаю, чем Git отличается от GitHub, и чем **clone** отличается от **fork**.

### Проверьте себя

1. Где находятся файлы после `git clone` — только на GitHub или также на компьютере?
2. Как узнать, какой репозиторий открыт в терминале?
3. Что значит `origin`?
4. Нужно ли создавать SSH-ключ или персональный токен для этого урока?
5. Почему не стоит сразу удалять папку, если `git clone` сообщает, что она уже существует?

**Готово, если:** Git запускается, локальная папка собственного репозитория найдена, `git status` работает и Codex видит именно этот проект. **Коммиты и отправку изменений будем делать позже.**
