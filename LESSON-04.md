# Урок 04. Условия и ветвление

**Время:** 45–75 минут (оценка)
**Уровень:** начинающий
**Пререквизиты:** пройдены [Урок 00](LESSON-00.md), [Урок 01](LESSON-01.md), [Урок 02](LESSON-02.md) и [Урок 03](LESSON-03.md). У вас есть работающий счётчик из Урока 03 и исходная кнопка «Поменять оформление».
**Результат:** вы можете объяснить, почему программа выбирает одно действие вместо другого, заранее предсказать ветку и лично проверить оба исхода.

> **Главная идея урока.** Программа не обязана выполнять все строки подряд. Условие позволяет выбрать: **если проверка истинна — сделай одно; иначе — сделай другое**. Сегодня вы добавите к своему счётчику сообщение, которое меняется после третьего нажатия.

## Чему научимся

После урока вы сможете:

1. Объяснить, что такое `true` и `false`.
2. Вычислить результат одного простого сравнения.
3. Заранее предсказать, какая ветка выполнится.
4. Найти обе ветки `if`/`else` в своём коде.
5. Объяснить, почему число `3` попадает в случай `clicks >= 3`.
6. Изменить порог, проверить его и вернуть прежнее поведение.
7. Отличить сообщение Codex от того, что вы увидели в браузере сами.
8. Объяснить, почему сообщение должно вычисляться из текущего значения счётчика, а не задаваться один раз вручную.

### Что НЕ понадобится

Ни нового проекта, ни библиотек, ни сервера, ни циклов, `switch`, вложенных условий, классов, TypeScript и новых инструментов. Работаем в том же `practice/lesson-01/index.html`, в том же редакторе и браузере.

> **Счётчик из Урока 03 обязателен, а необязательное упражнение `points` — нет.** Если у вас есть счётчик, продолжайте с ним. Дополнительный счётчик очков из шага Make Урока 03 не нужен ни для этого урока, ни для проверки.

## Шаг 1. Predict — сначала предсказываем (10 минут)

### Значение «да» или «нет»

Сравнение — это вопрос с двумя возможными ответами. Ответ `true` означает «да», а `false` — «нет»:

```javascript
clicks >= 3
```

Если `clicks` равно `3`, ответ — `true`. Если `clicks` равно `2`, ответ — `false`.

### Маленький пример

```javascript
let clicks = 0;
let message = '';

if (clicks >= 3) {
  message = 'Цель достигнута!';
} else {
  message = 'Продолжайте!';
}
```

Здесь:

- `if` пишется со строчной буквы, а условие стоит в круглых скобках;
- `clicks >= 3` читается как «`clicks` больше или равно `3`»;
- `if` выбирает первую ветку, когда условие — `true`;
- `else` выбирает вторую ветку, когда условие — `false`;
- в одном заходе выполняется **только одна** из двух веток.

**Предскажите до запуска.** Запишите сообщение для каждого значения:

| `clicks` | Ваше предсказание |
|---|---|
| `0` | |
| `2` | |
| `3` | |
| `4` | |

Почему `3` относится к первому случаю, хотя `3` не больше `3`? Знак `>=` означает «больше **или равно**».

## Шаг 2. Run — проверяем предсказание (10 минут)

### 1. Добавьте видимое сообщение

В HTML рядом со счётчиком добавьте один элемент:

```html
<span id="message">Продолжайте!</span>
```

Если у счётчика уже есть подпись, сообщение можно поставить после неё:

```html
<span>нажатий: <span id="counter">0</span></span>
<span id="message">Продолжайте!</span>
```

Сохраните файл.

### 2. Расширьте существующий обработчик

В Уроке 03 у вас уже есть обработчик нажатия, который увеличивает `clicks` и показывает число. **Не создавайте второй обработчик.** В том же блоке добавьте поиск сообщения и одно условие.

Конечный обрабатываемый кусок может выглядеть так:

```javascript
let clicks = 0;

function startCounter() {
  const countDisplay = document.querySelector('#counter');
  const themeButton = document.querySelector('#theme-button');
  const message = document.querySelector('#message');

  if (!countDisplay || !themeButton) {
    console.error('Счётчик не запущен: не найдены элементы #counter или #theme-button.');
    return;
  }

  if (!message) {
    console.error('Элемент #message не найден. Сообщение о достижении цели не будет показано.');
  }

  countDisplay.textContent = clicks;

  if (message) {
    if (clicks >= 3) {
      message.textContent = 'Цель достигнута!';
    } else {
      message.textContent = 'Продолжайте!';
    }
  }

  themeButton.addEventListener('click', function () {
    clicks = clicks + 1;
    countDisplay.textContent = clicks;

    if (!message) {
      return;
    }

    if (clicks >= 3) {
      message.textContent = 'Цель достигнута!';
    } else {
      message.textContent = 'Продолжайте!';
    }
  });
}

if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', startCounter);
} else {
  startCounter();
}
```

Это **канонический вариант**. Если в вашем коде счётчик устроен иначе, сохраните его рабочую логику и добавьте только `#message`, сравнение и `if`/`else` в существующий обработчик.

> **Почему нет второго обработчика?** Нажатие уже увеличивает `clicks`. Если добавить ещё один обработчик, который тоже увеличит счётчик, одно нажатие будет учтено дважды. Вместо «число нажатий» получится «число нажатий × 2».

> **Почему условие написано дважды?** Начальное сообщение и сообщение после нажатия вычисляются в разных местах, а функций мы пока не умеем выделять. Дублирование — осознанный шаг: его уберём в [Уроке 05](LESSON-05.md), где вынесем расчёт в отдельную функцию. Зато теперь сообщение всегда соответствует текущему значению `clicks` — даже если вы из Урока 03 начинали счётчик не с нуля.

> **Зачем проверка `if (!message)`?** Если элемента `#message` нет, счётчик всё равно должен работать: счётчик и сообщение — разные обязанности. Раньше при отсутствии `#message` страница просто молча переставала считать. Теперь в консоли появится понятная ошибка, а счётчик продолжит считать.

### 3. Проверьте обе ветки

1. Сохраните файл и обновите страницу (`F5`).
2. Сразу должно быть `Продолжайте!`.
3. Нажмите кнопку 2 раза: число должно стать `2`, сообщение — `Продолжайте!`.
4. Нажмите ещё раз: число должно стать `3`, сообщение — `Цель достигнута!`.
5. Нажмите ещё раз: число должно стать `4`, сообщение остаться `Цель достигнута!`.

| Нажатий | `clicks` | Ожидаемое сообщение | Совпало? |
|---|---|---|---|
| 0 | 0 | Продолжайте! | ☐ |
| 1 | 1 | Продолжайте! | ☐ |
| 2 | 2 | Продолжайте! | ☐ |
| 3 | 3 | Цель достигнута! | ☐ |
| 4 | 4 | Цель достигнута! | ☐ |

> **Проверка только значения `3` неполная.** Одна такая проверка даёт сведения только об этом входе и этом прогоне: она показывает, что при `clicks = 3` выполняется первая ветка. Чтобы убедиться в работе обеих веток, проверьте противоположную ветку (`2`) и значения около границы (`2`, `3`, `4`). Несколько успешных примеров не доказывают, что программа верна для любого входа, — но заметно повышают уверенность.

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Что даёт сравнение

Выражение `clicks >= 3` вычисляется в одно логическое значение:

- `clicks = 0`, `1` или `2` → `false`;
- `clicks = 3`, `4` или больше → `true`.

### Как выбирается ветка

Программа проверяет условие:

1. Если результат `true`, выполняется код внутри `if`.
2. Если результат `false`, выполняется код внутри `else`.
3. После этого программа идёт дальше по коду после блока.

Поэтому в одном `if`/`else` выполняется **ровно одна** ветка. При `clicks = 3` условие истинно, поэтому выполняется первая ветка, а `else` пропускается.

### Почему три — граница

Условие `clicks >= 3` включает само число `3`: «больше **или равно** `3`». Значит:

- `2` — ещё не цель;
- `3` — уже цель;
- `4` — цель тоже.

### Другие простые сравнения

Пока запомните форму, а не таблицу наизусть:

| Сравнение | Вопрос | Для `clicks = 3` |
|---|---|---|
| `clicks === 3` | ровно ли `3`? | `true` |
| `clicks !== 3` | не равно ли `3`? | `false` |
| `clicks < 3` | меньше ли `3`? | `false` |
| `clicks > 3` | больше ли `3`? | `false` |
| `clicks <= 3` | меньше или равно? | `true` |
| `clicks >= 3` | больше или равно? | `true` |

Знаки `===` и `!==` сравнивают значения на строгое равенство и неравенство. Здесь числу `3` соответствует число `3`, а не строка `"3"`.

## Шаг 4. Modify — меняем порог и возвращаем его (10 минут)

### Перед правкой — предскажите

Замените в сравнении `3` на `5`. Теперь условие будет `clicks >= 5`.

**Сначала запишите**, между какими значениями изменится сообщение. Затем сохраните и обновите страницу.

| `clicks` | Ожидаемое сообщение при пороге `5` | Совпало? |
|---|---|---|
| 4 | | ☐ |
| 5 | | ☐ |
| 6 | | ☐ |

Проверьте значение непосредственно **до** новой границы, **на** границе и **после** неё. Одной проверки на `5` недостаточно: она даёт сведения только об одном входе.

### Верните прежний порог

После проверки замените `5` обратно на `3`, сохраните файл и обновите страницу. Нажмите кнопку 3 раза: снова должно появиться `Цель достигнута!`. Это подтверждает восстановление прежнего поведения.

> **Помните:** условие `clicks >= 3` в этом уроке написано в двух местах — при первом выводе и внутри обработчика. Менять нужно **оба**. В [Уроке 05](LESSON-05.md) мы вынесем расчёт в функцию, и править станет достаточно один раз.

## Шаг 5. Make — выбираем условие сами (необязательно, 5–10 минут)

**Задача.** Пусть сообщение «Цель достигнута!» появляется не при `3`, а при `clicks > 5`.

1. Выберите одно сравнение из таблицы выше.
2. Запишите новое условие и границу **до** правки.
3. Измените только условие.
4. Проверьте значение непосредственно перед границей, на границе и после неё.
5. Запишите, какое сравнение выбрали и почему оно подходит.
6. Верните исходное условие `clicks >= 3` и проверьте три нажатия.

> **Подсказка, если трудно:** при `clicks = 5` условие «больше 5» ещё не истинно, а при `clicks = 6` уже истинно.

Не нужно вводить новые возможности JavaScript или менять тему оформления. Меняется только условие.

## Проверьте себя без подсказки

1. Что означают `true` и `false`?
2. Что вычислит `clicks >= 3`, если `clicks = 2`?
3. Какая ветка выполнится при `clicks = 3`?
4. Где в вашем коде находятся обе ветки?
5. Почему `3` входит в случай `clicks >= 3`?
6. Как изменить порог и какие три значения нужно проверить?
7. Как убедиться, что прежнее поведение восстановлено?
8. Что вы лично увидели в браузере, а что только написал Codex?
9. Что именно даёт проверка одного значения `3` — и чего она не даёт?
10. Что произойдёт, если удалить элемент `#message` из HTML?

> **Ответы (для самопроверки).** `true` — «да», `false` — «нет». При `clicks = 2` сравнение `clicks >= 3` даёт `false`, выполняется `else`. При `clicks = 3` оно даёт `true`, выполняется `if`. Знак `>=` включает саму границу, поэтому `3` уже достигает цели. Чтобы изменить порог, правят только число в сравнении и проверяют значение перед границей, на ней и после неё. Восстановление подтверждают прежним числом нажатий и тем же сообщением. Codex мог предложить текст кода, но наблюдением считается только то, что вы увидели в браузере. Проверка `3` показывает, что при этом входе выполняется первая ветка; она ничего не говорит о противоположной ветке и о входах рядом с границей, поэтому проверять нужно и `2`, и `4` — несколько успешных примеров повышают уверенность, но не дают математического доказательства для любого входа. Если удалить `#message`, в консоли появится сообщение «Элемент #message не найден…», а счётчик продолжит работать.

## Критерий завершения урока

Урок пройден, если вы **самостоятельно**:

1. Объясняете разницу между `true` и `false`.
2. Вычисляете простое сравнение.
3. Заранее предсказываете выбранную ветку.
4. Находите обе ветки в своём коде.
5. Объясняете поведение на границе.
6. Меняете порог и проверяете значения около новой границы.
7. Возвращаете исходное поведение и подтверждаете его.
8. Проверяете обе ветки, а не только значение `3`.
9. Отличаете заявление Codex от лично наблюдаемого результата.
10. Знаете, что сообщение вычисляется из текущего `clicks` и при первом выводе, и после каждого нажатия.
11. Понимаете, что при отсутствии `#message` счётчик продолжает работать, а в консоли появляется ошибка.

Шаг Make — **необязательный**. Упражнение `points` из Урока 03 для этого критерия не требуется.

Если что-то не получилось, запишите это прямо. **Не выдавайте ожидаемый результат за фактический** — это главный навык всего курса.
