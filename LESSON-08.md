# Урок 08. Массив объектов: несколько задач с собственными свойствами

**Время:** 45–75 минут (оценка)
**Уровень:** начинающий
**Пререквизиты:** пройдены [Урок 00](LESSON-00.md), [Урок 01](LESSON-01.md), [Урок 02](LESSON-02.md), [Урок 03](LESSON-03.md), [Урок 04](LESSON-04.md), [Урок 05](LESSON-05.md), [Урок 06](LESSON-06.md) и [Урок 07](LESSON-07.md). **Результат:** вы можете хранить несколько задач в одном массиве, брать нужную задачу по номеру, читать её именованные свойства, менять состояние одной задачи и предсказывать, как это повлияет на данные и на страницу.

Главное здесь — не новый синтаксис, а **смена представления данных**: то, как мы храним задачи, определяет то, как мы к ним обращаемся.

## Шаг 1. Predict — сначала предсказываем (10 минут)

### Что мы собираемся сделать

Сейчас в вашем файле два **независимых** учебных примера:

```javascript
const tasks = [
  'Прочитать главу',
  'Сделать упражнение',
  'Проверить результат'
];

const exampleTask = {
  title: 'Составить план',
  done: false
};
```

В `tasks` лежат **строки** — только названия. В `exampleTask` лежит **один** объект — одна задача с названием и состоянием.

А теперь представьте настоящий трекер задач. Задач не одна, а несколько. У каждой — **своё** название и **своё** состояние. Как это записать?

Можно было бы завести по две переменные на задачу, как мы думали в Уроке 07. Но мы уже знаем лучший способ: **массив**, в котором каждый элемент — **объект**.

Вот как это выглядит:

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false }
];
```

Снаружи — те же **квадратные скобки**, что и в Уроке 06. Внутри — те же **фигурные скобки**, что и в Уроке 07. Это всё, что изменилось.

> **Подсказка (только если совсем не получается).** Длина массива не изменилась: элементов по-прежнему **три**, поэтому `tasks.length` — `3`. `tasks[0].title` — это «**возьми первый элемент** массива, потом **возьми свойство** `title`». 3. **Замените массив строк на массив объектов.**

7. **Проверьте, что у каждой задачи есть и `title`, и `done`.**

Каноническое преобразование одного вызова:

```javascript
// Было
tasks.push('Повторить материал');

// Стало
tasks.push({
  title: 'Повторить материал',
  done: false
});
```

> **Главная ловушка — несовместимые типы.** Если вы замените объявление массива на объекты, но оставите старый строковый `push()`, в массиве окажутся **три объекта и одна строка**. `tasks.length` при этом всё равно покажет `4` — цифра правильная, а внутри всё сломано: у строки нет свойства `title`, поэтому `tasks[3].title` будет `undefined`, и задача выведется на странице как «`undefined`» или вообще исчезнет.
>
> **И вторая ловушка — дубль.** Если вы вставили четвёртую задачу **внутрь** литерала массива, но сохранили ещё и вызов `push()` с той же задачей — она попадёт в массив **дважды**. Задач будет пять, а одна из них повторится.
>
> Правило простое: **четвёртая задача добавляется одним способом — либо в литерале массива, либо отдельным вызовом `push()`, но не обоими сразу.**

**Форма 1 — четыре объекта в литерале массива:**

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false },
  { title: 'Написать отчёт', done: false }
];
```

**Форма 2 — три объекта плюс объектный `push()`:**

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false }
];

tasks.push({
  title: 'Написать отчёт',
  done: false
});
```

Обе формы дают **одинаковый** результат: `tasks.length` — `4`, номер четвёртой задачи — `3`, у неё есть и `title`, и `done`.

> **Но это не обязательно.** Канонический путь урока — **три** задачи. Четвёртая — ваш личный опыт, а не условие прохождения урока. Если её у вас не было — ничего не придумывайте, работайте с тремя.

### 3. Поправьте код показа — это главный момент урока

Откройте свой код и найдите то место, где вы показываете первую задачу. В Уроке 06 там было:

```javascript
  const firstTask = document.querySelector('#first-task');
  const taskCount = document.querySelector('#task-count');

  if (firstTask) {
    firstTask.textContent = tasks[0];
  }

  if (taskCount) {
    taskCount.textContent = tasks.length;
  }
```

**Здесь перестанет работать.** Почему: раньше `tasks[0]` был **строкой** — названием задачи, и её можно было сразу положить в `textContent`. Теперь `tasks[0]` — **объект**. Кладя объект в `textContent`, вы получите не название, а служебный текст вроде `[object Object]`.

Поэтому строку нужно поправить **ровно в одном месте**:

```javascript
  const firstTask = document.querySelector('#first-task');
  const taskCount = document.querySelector('#task-count');

  if (firstTask) {
    firstTask.textContent = tasks[0].title;
  }

  if (taskCount) {
    taskCount.textContent = tasks.length;
  }
```

> **Это и есть главное учебное наблюдение урока.** Мы изменили **представление данных**, и код, который эти данные показывает, пришлось обновить. Данные и отображение связаны: меняете данные — проверяете, что с ними делает код, который их читает. Именно это отличает инженера от того, кто просто копирует код.

> **Что НЕ изменилось.** Количество задач по-прежнему берётся из `tasks.length` — эта строка остаётся как была. Проверки `if` остаются на месте. Никаких новых обработчиков, никаких новых кнопок.

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Что такое массив объектов

Посмотрите на новый `tasks` и мысленно разделите его на две части:

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false }
];
```

- **Квадратные скобки `[ ... ]`** — это массив. Внутри **три** элемента, у них номера `0`, `1`, `2`.
- **Фигурные скобки `{ ... }`** — это объект. Внутри **два** свойства: `title` и `done`.
- **Каждая пара фигурных скобок — это один элемент массива.** То есть элемент массива здесь — не строка, а **целая задача**.

| Что | Как называется | Пример |
|---|---|---|
| `tasks` | **массив** — «ящик» с именем | `const tasks = [ ... ];` |
| `{ title: ..., done: ... }` | **объект-задача** — один элемент массива | `tasks[0]` |
| `title`, `done` | **свойства** — именованные признаки задачи | `tasks[0].title` |
| `'Прочитать главу'`, `false` | **значения** свойств | `tasks[0].done` |

### Два шага доступа: сначала номер, потом имя

Выражение `tasks[0].title` — это **два** действия, выполненные по очереди:

1. **`tasks[0]`** — взять элемент с номером `0`. Это шаг из Урока 06: номер элемента в массиве.
2. **`.title`** — взять свойство `title` у того, что получилось. Это шаг из Урока 07: имя свойства у объекта.

Порядок важен: сначала **достать** объект, потом обратиться к его свойству. Поэтому `tasks.title` — бессмыслица (у массива нет такого свойства), а `tasks[0].title` — правильно.

| Что пишем | Что получаем |
|---|---|
| `tasks.length` | `3` — количество **задач** |
| `tasks[0]` | объект-задача целиком |

### Массив — это не то же самое, что его элемент

Это различие стоит проговорить отдельно, потому что на нём строится весь урок.

| | Массив `tasks` | Задача `tasks[0]` |
|---|---|---|
| Что это | **коллекция** всех задач | **одна** задача |
| Что внутри | три **объекта** | два **именованных свойства** |
| Как достать | по **номеру**: `tasks[0]`, `tasks[1]` | по **имени**: `tasks[0].title` |
| Сколько всего | `tasks.length` → `3` | сколько свойств — видно по коду |

`tasks.length` — это «сколько **задач**», а `tasks[0].done` — «**выполнена ли первая**». Это разные вопросы к разным вещам, и путать их — источник большинства ошибок в этом уроке.

### Данные и то, что мы видим, — тоже разные вещи

Вспомните Урок 07. Там мы выяснили, что значение свойства и текст на странице — **разные вещи**:

- `tasks[0].done` — это **значение** в данных.
- Текст в `#first-task-status` — это **показанное представление**, которое записывается кодом при загрузке страницы.

Когда мы выводим состояние через `if`/`else`, мы **превращаем** `true`/`false` в слово «Выполнена»/«Не выполнена». Само свойство от этого не меняется — меняется только то, что мы **показываем**.

### Почему пришлось поправить `firstTask.textContent`

Вспомните ту правку из шага Run:

```javascript
firstTask.textContent = tasks[0];        // было в Уроке 06
firstTask.textContent = tasks[0].title;  // стало в Уроке 08
```

Причина — в **типе** того, что лежит в `tasks[0]`.

| | Урок 06 | Урок 08 |
|---|---|---|
| Что лежит в `tasks[0]` | строка `'Прочитать главу'` | объект `{ title: ..., done: ... }` |
| Что покажет `textContent = tasks[0]` | `Прочитать главу` | `[object Object]` |
| Что надо показать | `tasks[0]` | `tasks[0].title` |

Мы изменили **представление данных**, и код, который читает эти данные, пришлось обновить. Это нормальная и обязательная часть работы: меняете структуру — проверяете всех, кто с ней работает.

> **Как найти все такие места?** Попросите Codex: «Найди в файле все места, где используется `tasks`, и проверь, что каждое из них корректно работает с новым форматом массива». Это полезный навык: не «поправить первую ошибку», а «найти все потребителей данных».

### Что осталось независимым

`exampleTask` из Урока 07 — **отдельный** объект. Он **не** является элементом `tasks` и никак с ним не связан. Измените `tasks[0].done` — `exampleTask` не изменится. Мы не сливаем два учебных примера: мы учим массив задач **и** оставляем объект-пример как есть.

## Шаг 4. Modify — меняем состояние одной задачи (15 минут)

### Что мы собираемся сделать

Массив из Урока 06 позволял менять элементы, объект из Урока 07 — свойства. Сегодня мы сделаем **оба** сразу: поменяем состояние **одной** задачи внутри массива и посмотрим, что это изменит, а что — нет.

### Запишите предсказания ДО запуска

```javascript
tasks[0].done = true;
```

**Предскажите:**

1. Что вернёт `tasks[0].done` после этой строки? ___
2. Изменится ли `tasks[1].done`? ___
3. Изменится ли **текст** в `#first-task-status` на странице (без перезагрузки)? ___
4. Что будет показано в `#first-task-status`, если вы добавите строку `tasks[0].done = true;` **в файл** и перезагрузите страницу? ___

> **Важно.** Первый вопрос — про **данные**. Третий и четвёртый — про **показанный текст**. Это разные вещи (мы разбирали это в Уроке 07), и путать их — главная ошибка этого шага.

> **Подсказка (только если совсем не получается).** Первый вопрос — `true`: мы меняем свойство `done` у **первой** задачи. Второй вопрос — **не изменится**: у второй задачи **свой собственный** объект, и его `done` никто не трогал. Третий вопрос — **не изменится**: текст в `#first-task-status` был записан один раз, при загрузке страницы. Четвёртый вопрос — `Выполнена`: перезагрузка выполняет код из файла заново, и при загрузке страница записывает текст заново.

### Выполните — сначала только в консоли

Откройте консоль (`F12` → **Console**) и введите:

```javascript
tasks[0].done = true;
tasks[0].done
tasks[1].done
```

| Что | Ваше предсказание | Что показала консоль | Совпало? |
|---|---|---|---|
| Новое `tasks[0].done` | | | ☐ |
| `tasks[1].done` | | | ☐ |

Теперь посмотрите на **страницу**, не перезагружая её. Что написано в строке «Первая задача выполнена»?

| Что | Ваше предсказание | Что на странице | Совпало? |
|---|---|---|---|
| Состояние первой задачи на странице (без перезагрузки) | | | ☐ |

> **Ожидаемо:** в консоли `true`, у второй задачи `false`, а на странице по-прежнему `Не выполнена`. Это **не ошибка**: значение свойства изменилось, а показанный текст — нет.

### Проверьте страницу — перезагрузка без изменения файла

1. Сохраните файл (он ещё **не изменён**) и обновите страницу (`F5`).
2. В блоке «Ближайшая задача» должно быть: `Прочитать главу`, `Сделать упражнение`, `Не выполнена`, всего `3`.

| Что | Ожидаемо | Совпало? |
|---|---|---|
| Состояние первой задачи | `Не выполнена` | ☐ |
| Вторая задача | `Сделать упражнение` | ☐ |
| Всего задач | `3` | ☐ |

### Выполните — теперь в своём файле

Вставьте строку **в свой файл** — сразу после объявления `tasks` и **до** кода, который заполняет блок «Ближайшая задача»:

```javascript
const tasks = [
  { title: 'Прочитать главу', done: false },
  { title: 'Сделать упражнение', done: false },
  { title: 'Проверить результат', done: false }
];

tasks[0].done = true;
```

### Проверьте страницу ещё раз

1. Сохраните файл и обновите страницу (`F5`).
2. В блоке «Ближайшая задача» должно быть: `Прочитать главу`, `Сделать упражнение`, `Выполнена`, всего `3`.
3. Вторая задача как была `Не выполнена`? В нашем предпросмотре показывается только состояние **первой** задачи — поэтому визуально это не проверить. Проверьте в консоли: `tasks[1].done` — всё ещё `false`.

| Что | Ожидаемо | Совпало? |
|---|---|---|
| Состояние первой задачи | `Выполнена` | ☐ |
| `tasks[1].done` в консоли | `false` | ☐ |
| Вторая задача | `Сделать упражнение` | ☐ |
| Всего задач | `3` | ☐ |

### Почему вторая задача не изменилась

Потому что у каждой задачи — **свой** объект. `tasks[0]` и `tasks[1]` — это **два разных объекта**, у каждого свои свойства `title` и `done`. Мы изменили `done` **только** у первого. Второй объект мы вообще не трогали, поэтому его `done` остался `false`.

Это и есть та самая «собственность» из названия урока: **у каждого объекта — свои свойства**. Изменение одного не задевает остальные.

### Верните исходное состояние

Удалите строку `tasks[0].done = true;` из файла (или верните `done: false` у первой задачи), сохраните и обновите страницу. Состояние снова станет `Не выполнена`.

> **Проверка на «всё живое».** Нажмите кнопку счётчика, кнопку оформления, проверьте блок «Пример задачи» из Урока 07. Ничего не должно сломаться.

## Шаг 5. Make — добавляем задачу (необязательно, 10–15 минут)

> **Этот шаг необязательный.** Он не входит в критерий завершения урока и **не является условием для Урока 09**. Если времени нет — пропустите его и переходите к проверке.

Добавьте в массив **ещё одну задачу** — четвёртым элементом. Способ тот же, что и в Уроке 06, но элемент теперь **объект**:

```javascript
tasks.push({
  title: 'Написать отчёт',
  done: false
});
```

**Предскажите, не запуская:**

- Какой станет `tasks.length`? ___
- Под каким номером окажется новая задача? ___
- Какое у неё `title`? ___
- Какое у неё `done`? ___

| Что | Ваше предсказание | Что показала консоль | Совпало? |
|---|---|---|---|
| `tasks.length` | | | ☐ |
| `tasks[3].title` | | | ☐ |
| `tasks[3].done` | | | ☐ |

#### Как это сделать: в файле, а не в консоли

Здесь важно различать **три вещи**: **исходный код** (файл на диске), **состояние времени выполнения** (то, что сейчас в памяти браузера) и **то, что показано на странице**. Урок 08 учит именно это различение — не пропускайте его.

**Основной путь — добавить вызов в файл:**

1. Откройте свой `index.html` и найдите объявление `tasks`.
2. Добавьте вызов `push()` **сразу после** объявления массива:

   ```javascript
   const tasks = [
     { title: 'Прочитать главу', done: false },
     { title: 'Сделать упражнение', done: false },
     { title: 'Проверить результат', done: false }
   ];

   tasks.push({
     title: 'Написать отчёт',
     done: false
   });
   ```

3. **Сохраните файл** (`Ctrl+S` / `Cmd+S`).
4. **Обновите страницу** (`F5`).
5. Откройте консоль (`F12` → **Console**) и проверьте: `tasks.length` — `4`, `tasks[3].title` — `Написать отчёт`, `tasks[3].done` — `false`.
6. Посмотрите на страницу: в строке «Всего задач» должно быть **`4`**.

| Что | Как проверить | Ожидаемо |
|---|---|---|
| `tasks.length` | консоль, после перезагрузки | `4` |
| `tasks[3].title` | консоль, после перезагрузки | `Написать отчёт` |
| `tasks[3].done` | консоль, после перезагрузки | `false` |
| «Всего задач» на странице | обновить страницу | `4` |
| Тип четвёртого элемента | консоль: `tasks[3]` | объект `{ title: ..., done: ... }`, **не** строка |

> **А если выполнить эту строку только в консоли?** Введите в консоли `tasks.push({ title: 'Написать отчёт', done: false });` — и вы увидите `4` **прямо сейчас**, без сохранения файла. Это меняет **состояние времени выполнения**, но **не** изменяет **исходный код**. Обновите страницу (`F5`) — и массив снова будет из трёх задач, потому что страница выполняет код из файла, а не из памяти консоли.
>
> Правило простое: **состояние времени выполнения живёт до перезагрузки; исходный код живёт в файле.** Чтобы изменение пережило перезагрузку, его надо записать **в файл**.

> **Что теперь покажет страница?** Счётчик задач пересчитается сам: он читает `tasks.length`, поэтому после перезагрузки в поле «Всего задач» будет `4`. А вот названия на экране останутся прежними: мы по-прежнему показываем **только** первую и вторую задачи, написанные руками. Чтобы показать все четыре автоматически, нужен цикл — а это следующий урок.
>
> **Не добавляйте циклы, кнопки, генерацию HTML и сохранение данных.** Это упражнение — про `push()` для объекта, а не про новый способ показа задач.

## Что вы теперь умеете

| Раньше | Теперь |
|---|---|
| Массив — несколько **значений** по номерам | Массив — несколько **объектов** по номерам |
| `tasks[0]` — строка | `tasks[0]` — **объект-задача** |
| `tasks[0]` — это и есть название | `tasks[0].title` — название, `tasks[0].done` — состояние |
| Один объект `exampleTask` рядом с массивом | Массив задач, у каждой — свои свойства |
| `const` не мешает менять элемент массива | `const` не мешает менять **и** элемент массива, **и** свойство объекта |

**Что осталось на потом.** Мы научились хранить несколько задач и обращаться к каждой по номеру и по имени свойства. Но мы **по-прежнему** показываем задачи на экране вручную — по одной строке на задачу. Если задач станет двадцать, таких строк будет двадцать. Чтобы пройти по всем задачам одной командой, нужен **цикл**. Это ровно то, чем мы займёмся в следующем уроке.

## Источники подхода

Урок построен по схеме **PRIMM** (Predict → Run → Investigate → Modify → Make): [primmportal.com](https://primmportal.com/). Шаги Predict и Modify учат связывать выражение с наблюдаемым результатом и предсказывать состояние до изменения; порядок «сначала предсказать, потом запустить» опирается на исследования чтения и трассировки кода новичками (Busjahn & Schulte, 2013; Lister et al., 2004, 2009), перечисленные на странице [Research](https://primmportal.com/research/).

Идея урока — **последовательное усложнение одного и того же проекта**: ученик не переписывает приложение, а меняет представление данных в нём и наблюдает, какие части кода пришлось обновить. Это соответствует позиции курса: изменение структуры данных — обычная инженерная работа, и навык «найти всех потребителей данных и проверить их» важнее, чем новый синтаксис. Различение «наблюдения», «проверки контракта» и «формального доказательства» соответствует подходу курса (см. [CURRICULUM-DESIGN.md](CURRICULUM-DESIGN.md), раздел D.1a).
