## Что такое «значение», «переменная» и «выражение»

Четыре слова, которые понадобятся на всю оставшуюся жизнь. Разберём их на одном коротком примере.

```javascript
let clicks = 0;          // 1. объявление переменной и присваивание
clicks = clicks + 1;     // 2. выражение вычисляется, результат присваивается
```

| Строка | Что происходит |
|---|---|
| `let clicks = 0;` | Появляется **переменная** с именем `clicks`. В неё кладётся **значение** `0`. |
| `clicks = clicks + 1;` | Справа вычисляется **выражение** `clicks + 1`. Если `clicks` равен `0`, выражение даёт `1`. Этот `1` **присваивается** обратно в `clicks`. Теперь в переменной `1`. |

Теперь по одному.

### Значение (value)

**Значение** — это просто «что-то, что есть». Число `0`. Строка `"Привет"`. Истина или ложь. Значение **не** меняется само по себе — оно как число на бумажке: `5` всегда `5`.

### Переменная (variable)

**Переменная** — это **имя** для значения. `clicks` — имя; `0` — значение, которое лежит под этим именем прямо сейчас.

Представьте ящик с табличкой. Табличка — это имя (`clicks`). Внутри лежит число — это значение (`0`). Переставить табличку на другой ящик — значит изменить, что лежит под именем.

```javascript
let clicks = 0;   // ящик «clicks» теперь содержит 0
clicks = 5;       // а теперь тот же ящик содержит 5
```

**Ключевое свойство:** одна и та же переменная может хранить **разные** значения в разные моменты. Имя — постоянное, содержимое — нет.

### Присваивание (assignment)

**Присваивание** — это операция «положить значение в переменную». В JavaScript оно записывается знаком `=`.

> ⚠️ **Важная оговорка про `=`.** В математике `=` — это «равно». В JavaScript — **«присвоить»**. Когда вы пишете `clicks = 5`, вы **не спрашиваете** «равно ли?», а **говорите** «положи 5 в `clicks`».
>
> Сравнение — это **другая** операция, она записывается иначе: `===` (строгое равенство). Мы не разбираем её подробно — это отдельная тема, — но знайте, что **`=` и `===` — разные вещи**. Позже, в уроках про условия, мы вернёмся к этому подробно.

### Выражение (expression)

**Выражение** — это кусок кода, который **вычисляется в одно значение**. Оно отвечает на вопрос «что получится?». «`clicks + 1`» — выражение: подставьте текущее значение `clicks`, сложите, получите одно число.

```javascript
clicks + 1        // выражение → вычисляется в число
"a" + "b"         // выражение → вычисляется в строку "ab"
5 * 3             // выражение → вычисляется в 15
```

Но есть важная тонкость: **некоторые выражения ещё и меняют что-то** (у них есть **побочный эффект**). Присваивание — как раз такой случай:

```javascript
clicks + 1              // выражение: вычисляется в число, но clicks НЕ меняется
clicks = clicks + 1     // тоже выражение, но оно присваивает результат обратно в clicks
```

> **Правило для этого урока.** Одно выражение — это **значение**. Если результат никуда не записать, переменная останется прежней: строка `clicks + 1;` ничего не изменит. А строка `clicks = clicks + 1;` — уже **команда**: она вычисляет значение **и** записывает его в `clicks`.

### `let` и `const` — два способа объявить переменную

JavaScript требует сказать, что перед вами **новая переменная**. Для этого есть два слова:

```javascript
let clicks = 0;        // переменную можно будет переприсваивать
const answer = 42;     // значение задаётся один раз и не меняется
```

**Правило для этого урока:** `const` — значение задали один раз, менять нельзя; `let` — значение можно переприсваивать. Подробности и «когда что брать» — в справке ниже по шагу 1, её можно не читать сразу.

### Запасной путь: добавить самый маленький счётчик

Если переменных в вашем файле нет или счётчика нет — **добавьте минимальный счётчик**. Он понадобится для всех остальных шагов урока.

**Правка 2. Добавьте элемент, который будет показывать число.** Поставьте его **рядом с кнопкой**:

```html
<span id="counter">0</span>
```

**Правка 3. Добавьте сам счётчик** в блок `<script>` **в самый конец** (после всего остального кода):

```javascript
let clicks = 0;

function startCounter() {
  const countDisplay = document.querySelector('#counter');
  const themeButton = document.querySelector('#theme-button');

  if (!themeButton || !countDisplay) {
    return;
  }

  countDisplay.textContent = clicks;

  themeButton.addEventListener('click', function () {
    clicks = clicks + 1;
    countDisplay.textContent = clicks;
  });
}

if (document.readyState === 'loading') {
  document.addEventListener('DOMContentLoaded', startCounter);
} else {
  startCounter();
}
```

**Что здесь важного** (три коротких решения, без новой темы):

| Решение | Зачем |
|---|---|
| Ищем кнопку по `#theme-button`, а не по первому `button` | Нужная кнопка находится **точно**, даже если на странице есть другие кнопки |
| Ищем элементы **внутри `startCounter()`** | Если скрипт выполнился раньше HTML, элементы появятся только после разбора страницы — ищём их не раньше этого момента |
| Проверяем `themeButton` и `countDisplay` перед подключением | Если элемента нет, код не падает с ошибкой — просто ничего не подключается |
| `readyState` + `DOMContentLoaded` | Если скрипт выполнился **раньше**, чем HTML разобран, мы ждём готовности страницы. Если HTML уже готов — подключаем сразу |
| Показываем `clicks` при запуске | Начальное значение на экране совпадает со значением переменной: например, `10`, а не `0` |

<summary>Справка: `let` и `const` подробнее (можно не читать сразу)</summary>

| | `let` | `const` |
|---|---|---|
| Что означает | «давай будет **переменная**» | «давай будет **константа** — значение задано раз и всё» |
| Можно ли присвоить другое значение позже? | **Да** | **Нет** — будет ошибка |
| Когда брать | Значение будет меняться (счётчик, текущий текст, флаг) | Значение задаётся один раз и больше не меняется (ответ, имя элемента, настройка) |

> **Важное уточнение про `const`.** `const` запрещает менять **саму привязку** (само значение, записанное в переменную). Но `const` **не означает** «всё внутри неизменяемо». ## Шаг 3. Investigate — как выражение даёт результат (10 минут)

### Что происходит в строке `clicks = clicks + 1;`

Разберём по частям. Слева — что **хранится**, справа — что **вычисляется**.

```javascript
clicks = clicks + 1;
│       │  │   │  │
│       │  │   │  └── 1 — значение
│       │  │   └───── знак «плюс»
│       │  └───────── имя переменной (справа) — читаем её текущее значение
│       └──────────── знак присваивания
└──────────────────── имя переменной (слева) — куда положить результат
```

**Порядок выполнения — сначала вычисляется правая часть:**

1. Справа стоит выражение `clicks + 1`.
2. Чтобы его вычислить, нужно взять **текущее** значение `clicks`. Допустим, `0`.
3. Складываем: `0 + 1` → `1`.
4. Теперь слева: «положи `1` в `clicks`».
5. Переменная `clicks` теперь содержит `1`.

**Почему это важно:** выражение справа использует **старое** значение, а записывает результат — **новое**. Именно поэтому `clicks = clicks + 1` увеличивает счётчик на один, а не обнуляет его.

### Три вида значений, которых нам хватит

| Вид | Что это | Пример | Как выглядит в коде |
|---|---|---|---|
| **Число** | количество | `0`, `42`, `-3` | `let n = 0;` |
| **Строка** | текст | `"Привет"` | `let name = "Привет";` |
| **Логическое значение** | да или нет | `true`, `false` | `let ready = true;` |

**Строка** — это текст в кавычках. Кавычки важны: `5` — это **число**, а `"5"` — это **строка из одного символа**. Сами кавычки — только **границы** строки: они показывают, где текст начинается и кончается, и **внутрь** строки не входят. Поэтому у `"5"` ровно один символ: `"5".length` равно `1`. Их легко перепутать, потому что `typeof "5"` даёт `"string"`, а `typeof 5` даёт `"number"`.

**Логическое значение** — это «да» или «нет». Оно получается из сравнений: `clicks > 0` — это `true`, если кликов больше нуля. Само сравнение мы подробно не разбираем — это тема следующих уроков, — но увидеть результат стоит уже сейчас.

## Шаг 4. Modify — меняем одно значение (10 минут)

**Правило одного изменения за раз.** Меняете одну вещь — и сразу проверяете.

### Сначала — запишите свою базу

Прежде чем что-то менять, **запишите в заметку** (можно в блокнот рядом с компьютером):

| Что записать | Как найти |
|---|---|
| **Где инициализируется** счётчик | строка, где переменная объявляется (`let clicks = 0;` или что-то похожее у вас) |
| **Какое начальное значение** стоит там сейчас | число справа от `=` |
| **Где значение меняется** | строка, где счётчику присваивают новое значение |
| **Как считается новое значение** | по какой формуле (у каноничного примера: `clicks = clicks + 1`) |

> **Важно.** Ваш счётчик может называться иначе (`counter`, `count`, `presses`) и расти по-другому. Это нормально. Ниже примеры на **каноническом** коде (`let clicks = 0;` и `clicks = clicks + 1;`) — но работать нужно с **вашей** строкой и **вашей** формулой. Если ваш счётчик намеренно начинается с другого числа — считайте **от своей базы**, а не от нуля.

### Выберите одно изменение

| Вариант | Что меняете | Что увидите (для каноничного примера) |
|---|---|---|
| **A** | начальное значение счётчика (например, `0` → `10`) | счётчик начнёт с `10` |
| **B** | **шаг** увеличения (например, `+ 1` → `+ 2`) | счётчик будет прыгать через один: `2`, `4`, `6` |
| **C** | текст, который видит человек рядом со счётчиком | изменится подпись |

### Как это сделать

**Вариант A.** Найдите **свою** строку инициализации и замените начальное значение (например, `0` → `10`).

**Вариант B.** Найдите **свою** строку, где счётчик меняется, и замените **число прибавляемое** (например, `+ 1` → `+ 2`). ⚠️ Меняйте **только** это число — не имя переменной и не что-то в соседней строке.

**Вариант C.** Найдите в HTML элемент, который показывает число, и добавьте рядом с ним текст-подпись (например, `<span id="counter">0</span>` → `<span>нажатий: </span><span id="counter">0</span>`).

### Перед правкой — предскажите

**Запишите, что произойдёт**, прежде чем сохранять файл. Это главная часть упражнения.

Например, для варианта B и каноничного кода: «после первого нажатия будет `2`, после второго `4`, после третьего `6`». Если у вас другой шаг — пересчитайте от своей базы.

### После правки — проверьте

1. Сохраните файл.
2. Обновите страницу в браузере (`F5`, или `Ctrl` + `F5`, если не обновилось).
3. Нажмите кнопку 3 раза.
4. Сравните с предсказанием.

| Вариант | Ожидаемое после 3 нажатий (каноничный код) | Совпало? |
|---|---|---|
| A | `13` (10 + 1 + 1 + 1) | ☐ |
| B | `6` (2 + 2 + 2) | ☐ |
| C | число `3` и новая подпись | ☐ |

**Не совпало?** Вернитесь к таблице трассировки из Шага 2 и пройдите по ней заново, подставляя **новые** значения. Найдите строку, где ожидание разошлось с фактом.

### Верните всё как было

Эксперимент закончен — **верните изменённое значение назад**. Это обязательный шаг: следующее упражнение (Make) считает от базового поведения, и если оставить `+ 2` или `10`, примеры ниже перестанут сходиться.

| Вариант | Что вернуть |
|---|---|
| A | начальное значение обратно (`10` → `0`) **и запись `countDisplay.textContent = clicks;` в `startCounter()` оставьте** — тогда надпись снова совпадёт с переменной |
| B | шаг обратно (`+ 2` → `+ 1`) |
| C | текст-подпись — либо уберите её, либо оставьте: это не влияет на числа |

**Как проверить, что вернули:**

1. Сохраните файл и обновите страницу.
2. Нажмите кнопку **1** раз — должно быть `1` (для каноничного кода).
3. Нажмите ещё раз — должно быть `2`.

Если числа снова идут не так, как раньше, — ищите строку, которую вы меняли, и сравните с тем, что записали в начале шага.

> **Не нужно «откатывать» всё подряд.** Верните только то, что меняли в этом шаге. Ваши собственные осмысленные изменения (например, другой `id` у кнопки или добавленный `#points`) — **оставьте**. Никакие команды Git для этого не нужны: правка в редакторе и есть откат.

## Шаг 5. Make — применяем к похожей, но другой задаче (10 минут)

Это шаг, который отличает «я повторил инструкцию» от «я понял». Задача **похожа**, но **не та же**.

### Задание

**Сделайте так, чтобы на странице показывались сразу два числа: сколько раз нажата кнопка и сколько за это начислено очков.**

Правило начисления: **каждое нажатие приносит 2 очка.**

Подсказка: у вас уже есть первая «вещь, которая меняется» — число нажатий. Вторую можно вывести **из** первой: `points = clicks * 2`. Но в этом шаге полезнее завести **отдельную переменную** `points` и обновлять её **рядом** с первой — так вы увидите, что в программе может быть несколько связанных значений.

**Ограничения:**
- менять только `practice/lesson-01/index.html`;
- новая переменная объявляется через `let` (её значение будет меняться);
- без новых библиотек, без циклов и без условий.

### Как это может выглядеть

Не **обязано** так — это пример. Ваше решение может отличаться:

**JavaScript** (в блоке `<script>`). Ниже — как будет выглядеть **весь** обрабатываемый кусок после ваших правок:

```javascript
let clicks = 0;
let points = 0;

const countDisplay = document.querySelector('#counter');
const pointsDisplay = document.querySelector('#points');

themeButton.addEventListener('click', function () {
  clicks = clicks + 1;
  points = points + 2;
  countDisplay.textContent = clicks;
  pointsDisplay.textContent = points;
});
```

> **Внимание: это не «ещё один блок», а замена старого.** Добавьте **две** новые строки (`points = points + 2;` и `pointsDisplay.textContent = points;`) **внутрь** уже существующего обработчика нажатия и добавьте **одну** строку `let points = 0;` рядом с `let clicks = 0;`. Если вы **приклеите** этот пример вторым блоком, у страницы окажется **два** обработчика и счётчик будет прыгать через два — это заметно и это ошибка.
>
> **`themeButton`** — это имя кнопки из запасного пути. Если у вас кнопка называется иначе (`button`, `themeBtn`) — поставьте **своё** имя.

**HTML** (рядом с кнопкой, рядом со счётчиком):

```html
<span>нажатий: <span id="counter">0</span></span>
<span>очков: <span id="points">0</span></span>
```

Обратите внимание на **три** вещи:

1. Переменная `points` объявлена **через `let`** и живёт **рядом** с `clicks`.
2. Она меняется **в том же** обработчике нажатия — там же, где `clicks`.
3. Для неё есть **свой** элемент `#points`, и в `.textContent` попадает **именно** `points`, а не `clicks`.

### Как проверить (на нулевой базе)

Если ваш счётчик сейчас начинается с `0` и растёт на `1` за нажатие, таблица такая:

| Нажатий | `clicks` | `points` |
|---|---|---|
| 0 | 0 | 0 |
| 1 | 1 | 2 |
| 2 | 2 | 4 |
| 3 | 3 | 6 |

**Если у вас другая база** (например, счётчик начинается с `10` или растёт на `2`) — пересчитайте таблицу **от своей базы** и запишите её. Это и есть настоящая проверка: не «как в примере», а «как у меня».

> **Не копируйте слепо.** Сначала попробуйте **сами**: где в вашем коде увеличивается первый счётчик? Как туда же добавить второй? Что вы покажете в его элементе? Потом сверьте с примером.

### Проверка

- [ ] На странице **видны два числа**, и оба меняются при нажатии.
- [ ] Очки **вдвое больше** числа нажатий — и вы можете объяснить, почему.
- [ ] Вы можете объяснить, **где** в коде живёт каждое значение и **в какой** элемент оно выводится.
- [ ] После перезагрузки страницы оба числа снова `0` — никуда не сохранялись.

> **Этот шаг необязательный.** Если времени мало или упражнение не получается — **пропустите его** и идите к следующему шагу. Критерий завершения урока его не требует.

## Шаг 6. Проверяем себя (5 минут)

### Чек-лист наблюдаемого результата

**Каждый пункт вы ставите сами, глядя на экран или в свой код.**

- [ ] В моём файле есть **хотя бы одна** переменная, и я знаю её **имя**.
- [ ] Я знаю, **какое** значение в ней лежит прямо сейчас.
- [ ] Я нашёл строку, где это значение **меняется**, и могу её объяснить.
- [ ] Я **предсказал** результат выражения **до** запуска и сверился с фактом.
- [ ] Я **внёс** одно изменение и **лично проверил** результат в браузере.
- [ ] После эксперимента я **вернул** исходное поведение и проверил, что всё снова как раньше.
- [ ] Я знаю, чем `=` отличается от `===`, хотя полное сравнение разберём позже.
- [ ] *(если делали шаг Make)* Я завёл **вторую** переменную, **показал оба значения на странице** и объяснил, где каждое живёт.
- [ ] Я знаю, **что именно** проверил, а что — нет.

### Разбор изменений

Посмотрите, что Git показывает о ваших правках:

```powershell
git status --short
git diff
```

| Что вы сделали | Что увидите |
|---|---|
| Изменили файл, который Git **уже отслеживает** | `git diff` покажет построчно: строки с `+` — добавленные, со `-` — удалённые |
| Создали **новый** файл | `git status --short` покажет его с меткой `??` (untracked, «ещё не отслеживается») |
| Изменили файл, который **ещё не отслеживается** (например, ваш `practice/lesson-01/index.html`, который остался `??` после Урока 01) | `git diff` **не покажет** содержимое изменений, а `git status --short` — покажет сам файл как `??` |

> **Важно.** Пустой `git diff` **не означает**, что изменений нет. Если ваш файл ещё не добавлен в Git (а в Уроке 01 он остался новым файлом), обычный `git diff` промолчит — даже если вы переписали его целиком. Чтобы увидеть правки в таком файле, откройте **сам файл** в редакторе или попросите Codex показать его содержимое.
>
> Отслеживание файлов, добавление в индекс и коммиты — тема отдельных уроков. Здесь мы только **смотрим**, ничего не добавляя и не коммитя.

### Ответьте сами (без подсказки)

1. Что такое **значение**, **переменная**, **присваивание**, **выражение** — своими словами?
2. Чем `let` отличается от `const`?
3. Что означает `=` и чем это отличается от `===`?
4. Почему присваивание `clicks = clicks + 1` увеличивает счётчик, а не обнуляет его?
5. Почему `"5" + 1` даёт `"51"`, а `5 + 1` даёт `6`?
6. Что сделал Codex в этом уроке — и что вы проверили **сами**?

> **Ответы (для самопроверки).** (1) Значение — «что-то, что есть»; переменная — имя для значения; присваивание — «положить значение в переменную»; выражение — кусок кода, который вычисляется в одно значение; некоторые выражения (например, присваивание) дополнительно **меняют** переменную. (2) `let` — значение можно переприсваивать, `const` — задаётся один раз; `const` не делает содержимое объектов неизменяемым. (3) `=` — присваивание, `===` — сравнение. (4) Правая часть вычисляется из **старого** значения, результат записывается **после**. (5) В первом случае складывается строка, и число превращается в строку; во втором — складываются числа. (6) Codex мог объяснить код; проверку вы делали сами.

## Критерий завершения урока

Урок пройден, если вы **самостоятельно**:

1. **Нашли** переменную в своей программе и назвали её.
2. **Объяснили**, какое значение в ней лежит изначально.
3. **Проследили**, как значение меняется от строки к строке.
4. **Отличаете** присваивание `=` от сравнения `===` на уровне «что делает» — без разбора всех операторов сравнения.
5. **Предсказали** результат одного простого выражения **до** запуска.
6. **Внесли** одно ограниченное изменение, **лично проверили** его в браузере и **вернули** исходное поведение.
7. **Объяснили**, что делал Codex и что вы проверили **сами**.

Шаг Make (вторая переменная и два видимых значения) — **необязательный**: его можно пропустить, критерий его не требует.

Если что-то не получилось, запишите это прямо. **Не выдавайте ожидаемый результат за фактический** — это главный навык всего курса.
