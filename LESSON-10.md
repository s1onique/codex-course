# Урок 10. Изменение состояния: отмечаем задачу выполненной

**Время:** 45–75 минут (оценка)
**Уровень:** начинающий
**Пререквизиты:** пройдены [Урок 00](LESSON-00.md), [Урок 01](LESSON-01.md), [Урок 02](LESSON-02.md), [Урок 03](LESSON-03.md), [Урок 04](LESSON-04.md), [Урок 05](LESSON-05.md), [Урок 06](LESSON-06.md), [Урок 07](LESSON-07.md), [Урок 08](LESSON-08.md) и [Урок 09](LESSON-09.md). У вас есть работающая страница со счётчиком, сообщением «Цель достигнута!», кнопкой «Поменять оформление», функцией `achievementMessage()`, массивом `tasks` из трёх объектов-задач, блоком «Задачи» со списком `<ul id="task-list">`, строкой «Всего задач: <span id="task-count">» и функцией `renderTaskList()`, которая строит список из данных.
**Результат:** вы можете объяснить, как событие вызывает изменение состояния задачи, и написать функцию, которая меняет данные **и** явно обновляет страницу — без перезагрузки.

> **Главная идея урока.** До сих пор страница **смотрела** на задачи, но не **меняла** их по нажатию кнопки. Сегодня мы сделаем первое настоящее изменение состояния по действию пользователя. Ключевая мысль урока звучит так: **изменение данных и показ данных — это две разные операции**. Сначала меняем данные, потом **явно** говорим странице: «покажи их заново».

## Шаг 1. Predict — сначала предсказываем (10 минут)

### Что мы собираемся сделать

После Урока 09 страница умеет показывать список задач. Но она делает это **один раз** — при загрузке. Покажем это прямо: откройте консоль (`F12` → **Console**) и выполните

```javascript
tasks[0].done = true;
```

Посмотрите на страницу. Список **не изменился** — там всё ещё «Не выполнена». Данные изменились, а показанный текст — нет.

Сегодня мы добавим **одну** кнопку, которая делает ровно это правильно: меняет данные **и** сразу обновляет страницу.

### Главная модель урока

Всё, что мы сегодня сделаем, укладывается в одну цепочку:

**Событие → изменение состояния → показ → наблюдаемый результат.**

Читается она так: **нажали кнопку** (событие) → **изменилось поле `done` у задачи** (изменение состояния) → **вызвалась функция показа** (показ) → **на странице появилось «— Выполнена»** (наблюдаемый результат).

### Запишите предсказания ДО запуска

Ответьте на эти шесть вопросов **до** того, как напишете код. Это главная часть шага.

1. Состояние (`done`) первой задачи **до** нажатия — какое? ___
2. Состояние первой задачи **после первого** нажатия — какое? ___
3. Состояние первой задачи **после второго** нажатия — какое? ___
4. Изменится ли что-нибудь у **второй** задачи? ___

6. Что произойдёт, если задач вообще **не будет** (`tasks` — пустой массив)? ___

> **Не подглядывайте дальше, пока не запишете.** Если предсказание потом не совпало — это отличный результат, а не провал: значит, вы нашли границу, о которой не подумали. Запишите, в каком пункте ошиблись и почему.

## Шаг 2. Run — делаем кнопку и функцию (15 минут)

### 1. Добавьте кнопку на страницу

В том же блоке «Задачи», где уже есть `<ul id="task-list">`, добавьте **одну** кнопку — **до** списка или **после** него, на ваш вкус:

```html
<section>
  <h2>Задачи</h2>
  <ul id="task-list"></ul>
  <p>Всего задач: <span id="task-count">—</span></p>
  <button id="complete-first-task">
    Завершить первую задачу
  </button>
</section>
```

> **Одна кнопка — на весь урок.** Мы **не** делаем кнопку на каждую задачу. Это сознательное решение: сегодня учимся **одной** операции изменения состояния, а не разбираемся с тем, как построить интерфейс для многих задач. Кнопку на выбранную задачу добавим позже.

### 2. Напишите функцию, которая меняет состояние

Добавьте в свой файл **отдельную функцию** — рядом с `renderTaskList()`, по правилам Урока 05:

```javascript
function completeFirstTask() {
  if (tasks.length === 0) {
    console.error('Нет задач для завершения');
    return;
  }

  tasks[0].done = true;
  renderTaskList();
}
```

Что здесь происходит — **по порядку**:

| Строка | Зачем она |
|---|---|
| `if (tasks.length === 0) { ... return; }` | **защита**: если задач нет, пишем понятное сообщение в консоль и **выходим**. Иначе `tasks[0]` — это `undefined`, и следующая строка упала бы с ошибкой |
| `console.error('Нет задач для завершения');` | сообщение **для вас**, а не для пользователя: на странице ничего не ломается |
| `tasks[0].done = true;` | **изменение данных**: у первой задачи состояние становится «выполнена» |
| `renderTaskList();` | **показ**: явно говорим странице показать список заново, с новым состоянием |

> **`tasks[0]` — это первая задача.** Мы уже знаем это из Урока 06: элементы массива нумеруются с нуля, поэтому «первая» задача — это `tasks[0]`, вторая — `tasks[1]`.
>
> **`done = true` — это изменение данных.** Ровно то, что мы делали в Уроке 08, только теперь по нажатию кнопки, а не вручную в консоли.
>
> **`renderTaskList()` — это показ.** Функция из Урока 09. Она **не** меняет данные — она читает их и записывает в страницу.

### 3. Подключите кнопку — в уже знакомом месте

В том же месте, где вы в Уроке 09 вызвали `renderTaskList()` (в Уроке 08 это `startCounter()`), добавьте **одно** подключение:

```javascript
  const completeButton = document.querySelector('#complete-first-task');

  if (!completeButton) {
    console.error('Не найдена кнопка завершения задачи');
  } else {
    completeButton.addEventListener('click', completeFirstTask);
  }
```

Что здесь происходит:

| Строка | Зачем она |
|---|---|
| `document.querySelector('#complete-first-task')` | находим кнопку на странице — тот же приём, что и раньше |
| `if (!completeButton) { console.error(...); }` | **защита**: если кнопки нет, **говорим об этом** и **не** пытаемся подключить обработчик. Страница не должна падать |
| `addEventListener('click', completeFirstTask)` | **одна** подписка: при клике вызывается наша функция |

> **Где именно подключать.** Обработчик подключается **один раз**, в существующей функции инициализации — **не** внутри `renderTaskList()`. Иначе при каждом показе списка на кнопку добавлялся бы ещё один обработчик, и одно нажатие вызывалось бы функцией несколько раз. Правило простое: **подписка — один раз при загрузке, показ — сколько угодно раз.**

### 4. Сделайте так, чтобы список и количество обновлялись вместе

Сейчас в вашем файле количество задач показывает **старая** строка в функции инициализации, а список — `renderTaskList()`. Это две разные вещи, которые легко рассинхронизировать: список может показать четыре пункта, а «Всего задач» — по-прежнему `3`.

**Перенесите ответственность за количество в `renderTaskList()`.** Добавьте в функцию показа **одну** защищённую строку — сразу после проверки `list`:

```javascript
function renderTaskList() {
  const list = document.querySelector('#task-list');

  if (!list) {
    console.error('Не найден список задач');
    return;
  }

  const count = document.querySelector('#task-count');

  if (count) {
    count.textContent = String(tasks.length);
  }

  list.textContent = '';

  for (const task of tasks) {
    const item = document.createElement('li');

    if (task.done) {
      item.textContent = task.title + ' — Выполнена';
    } else {
      item.textContent = task.title + ' — Не выполнена';
    }

    list.appendChild(item);
  }
}
```

Что изменилось по сравнению с Уроком 09:

- **Появилось** три строки: найти `#task-count`, проверить, что он есть, и записать в него `tasks.length`.
- `String(tasks.length)` — превращаем число в строку, потому что `textContent` принимает **текст**. Это тот же приём, что в Уроке 08, где вы писали `String(tasks.length)` в счётчик.

А **старую** строку, которая записывала количество в `#task-count` из функции инициализации, **удалите** — иначе количество будет обновляться в двух местах, и рано или поздно эти места разойдутся.

> **Один владелец — одно правило.** Теперь **всё**, что показывается про задачи, обновляет **одна** функция: `renderTaskList()`. Она отвечает и за список, и за количество. Это не «архитектура» и не «паттерн» — это просто удобно: правило «что показывать» живёт в одном месте.
>
> Урок 09 при этом **остаётся верным**: там количество всё ещё пишется при загрузке страницы, и для первоначального показа этого достаточно. Сегодня мы **улучшаем** владение показом, а не ломаем то, что уже работает.

| Действие | `tasks[0].done` | Надпись у первого пункта | «Всего задач» |
|---|---|---|---|
| Загрузка страницы | `false` | Не выполнена | `3` |
| Первое нажатие | `true` | Выполнена | `3` |
| Второе нажатие | `true` | Выполнена | `3` |

>
> **Почему после перезагрузки всё как было.** Мы не сохраняли данные никуда. Страница выполняет код **из файла**, а в файле `done: false`. Мы это уже знаем из Урока 08 — «состояние времени выполнения живёт до перезагрузки».

## Шаг 3. Investigate — разбираем, что произошло (15 минут)

### Цепочка целиком

Когда вы нажали кнопку, произошло ровно пять вещей, **по порядку**:

1. **Событие.** Браузер заметил клик по `#complete-first-task` и вызвал обработчик.
2. **Вызов функции.** Обработчик — это `completeFirstTask`, поэтому функция **вызвалась**.
3. **Изменение данных.** Внутри выполнилось `tasks[0].done = true;` — изменилось состояние задачи.
4. **Показ.** Следующей строкой вызвалась `renderTaskList()` — функция пересобрала список и записала новое количество.
5. **Наблюдаемый результат.** На странице появилось «— Выполнена».

### Две разные функции — две разные обязанности

| Функция | Что делает | Что **не** делает |
|---|---|---|
| `completeFirstTask()` | **меняет** данные: `tasks[0].done = true` | не трогает страницу напрямую |
| `renderTaskList()` | **показывает** данные: строит список и пишет количество | не меняет `done` ни у одной задачи |

Это разделение — и есть главная мысль урока. Функция, которая меняет состояние, **не обязана** знать, как выглядит страница. Функция, которая показывает, **не обязана** знать, что именно изменилось. Связывает их одна строка: `renderTaskList();` внутри `completeFirstTask()`.

### Почему `renderTaskList()` без изменения данных не завершает задачу

Попробуйте в консоли выполнить **только** показ:

```javascript
renderTaskList();
```

Список перерисуется. Но `done` у задач **не изменится** — это функция **показа**, а не изменения. Задача останется «Не выполнена». Показ не может выполнить задачу за вас.

### Почему изменение без показа оставляет старый текст

А теперь наоборот — измените данные **без** показа:

```javascript
tasks[0].done = true;
```

`tasks[0].done` теперь `true` — это можно проверить в консоли. Но текст на странице **остался** «Не выполнена».

**Почему?** Потому что страница не следит за данными сама. Текст в `<li>` был записан **один раз**, когда функция показа отработала при загрузке страницы. Чтобы текст обновился, функцию показа надо **вызвать снова**. Именно поэтому в `completeFirstTask()` две строки, а не одна.

> **Это и есть та самая «разница между данными и показанным текстом»,** которую мы разбирали в Уроках 07, 08 и 09. Сегодня мы сделали шаг вперёд: мы не просто **знаем** про эту разницу — мы **умеем** её закрывать одним вызовом.


### Что такое идемпотентность и почему она здесь

Вы нажали кнопку три раза, и результат **не испортился**. Это свойство называют **идемпотентностью**.

**Идемпотентная операция** — это операция, которую можно выполнить повторно, и результат останется тем же. Повторное «завершить задачу» не создаёт **нового** изменения: задача и до повтора была выполненной, и после — выполненная. Состояние просто **уже было** `true`, и мы записали `true` ещё раз.

**Почему это хорошо.** Без этого качества повторное нажатие могло бы, например, увеличить счётчик выполненных задач вдвое или переключить состояние «выполнена → не выполнена». Наша операция **не** переключает, а **устанавливает**: `done = true` всегда означает «выполнена».

> **Если первая задача уже была выполнена** (например, вы оставили `done: true` в файле), кнопка ничего не испортит: она запишет `true` в `true` и перерисует список. Тот же результат.

### Что такое состояние и переход состояния

**Состояние** — это текущее значение, которое имеет задача. Для нас это поле `done`: у задачи оно бывает `true` (выполнена) или `false` (не выполнена).

**Переход состояния** — это **переход** из одного допустимого значения в другое. Наш переход: `done: false` → `done: true`. «Допустимых» значений у задачи ровно **два**, и мы не заводим новых.

| Что | Как это выглядит в коде |
|---|---|
| Состояние | `tasks[0].done` — значение `true` или `false` |
| Переход состояния | `tasks[0].done = true;` — смена значения |
| Функция перехода | `completeFirstTask()` — делает переход и запускает показ |
| Показ | `renderTaskList()` — показывает текущие данные |

> **Мы не строим конечный автомат.** Это первое знакомство с идеей «состояние меняется по событию». Формальная нотация автоматов, несколько состояний кроме «выполнена / не выполнена» и строгие контракты — это **позже** и **не сегодня**. Сегодняшняя задача — почувствовать цепочку **событие → изменение → показ → результат** на знакомом коде.

| Пунктов в списке | ровно **три**, без дублей |
| «Всего задач» | `3` — задач не добавилось, изменилось только состояние |

> **Почему «Всего задач» не изменилось.** Потому что мы изменили **состояние** задачи, а не **количество** задач. Количество — это `tasks.length`, длина массива. Состояние на длину не влияет. Хорошая проверка: если после вашей правки счётчик «поехал» — значит, вы изменили что-то ещё.

### Верните как было

Поставьте обратно `tasks[0].done = true;`, сохраните, обновите страницу. Убедитесь, что кнопка снова завершает **первую** задачу.

## Шаг 5. Make — своя функция (необязательно, 10–15 минут)

> **Этот шаг необязательный.** Он не входит в критерий завершения урока и **не является условием для Урока 11**. Если времени нет — пропустите его и переходите к проверке.

**Задача.** Напишите функцию, которая отмечает **любую** задачу как выполненную, — по номеру.

Мы уже умеем передавать значение в функцию — это **параметр** из Урока 05. Вспомните: функция объявляет, какие значения ей нужны, а при вызове мы передаём конкретные.

```javascript
function completeTaskByIndex(index) {
  if (index < 0 || index >= tasks.length) {
    console.error('Нет задачи с номером ' + index);
    return;
  }

  tasks[index].done = true;
  renderTaskList();
}
```

И вызов, например, для третьей задачи (нумерация с нуля!):

```javascript
completeTaskByIndex(2);
```

**Проверьте:**
- изменилось состояние **только** третьей задачи;
- список перерисовался без дублей;
- «Всего задач» не изменилось;
- `completeTaskByIndex(99)` **не** ломает страницу — только пишет в консоль понятное сообщение.

> **Почему здесь `index >= tasks.length`.** Так вы ловите номер, которого **нет**. Без этой проверки `tasks[99]` — это `undefined`, и строка `tasks[99].done = true` упала бы с ошибкой. Это тот же приём, что и защита `tasks.length === 0` в `completeFirstTask()`, только для конкретного номера.

> **Новые кнопки не нужны.** Вызвать функцию можно из консоли — этого достаточно, чтобы увидеть результат. Мы **не** добавляем кнопку на каждую задачу: это отдельная тема.

## Что вы теперь умеете

| Раньше | Теперь |
|---|---|
| Страница показывала задачи **один раз** — при загрузке | Страница **перерисовывается** после действия пользователя |
| Изменить задачу можно было только вручную в консоли | Изменение происходит **по нажатию кнопки** |
| Данные и показ были связаны случайно | Данные меняет **одна** функция, показывает — **другая** |
| Количество задач считалось в старом месте | Список **и** количество обновляет **одна** функция `renderTaskList()` |
| Повторное действие могло бы всё испортить | Повторное завершение — **идемпотентная** операция: тот же результат |

**Что осталось на потом.** Сегодня мы меняли состояние **одной, заранее выбранной** задачи — той, что стоит первой в массиве. Урок 11 научит завершать **выбранную** пользователем задачу: по-прежнему это правильно, но требует ещё одного понятия — как страница должна сообщить программе, **какую** задачу выбрали. Конечные автоматы и строгие контракты придут позже — сначала нужно уверенно почувствовать, что переход состояния и показ — это **две отдельные операции**, которые нужно выполнять в правильном порядке.

## Источники подхода

Урок построен по схеме **PRIMM** (Predict → Run → Investigate → Modify → Make): [primmportal.com](https://primmportal.com/). Шаги Predict и Modify учат связывать событие с наблюдаемым результатом и предсказывать состояние до изменения; порядок «сначала предсказать, потом запустить» опирается на исследования чтения и трассировки кода новичками (Busjahn & Schulte, 2013; Lister et al., 2004, 2009), перечисленные на странице [Research](https://primmportal.com/research/).

Идея урока — **последовательное усложнение одного и того же проекта**: ученик не переписывает приложение, а добавляет в него **одно** действие пользователя и связывает изменение данных с обновлением показа. Это соответствует позиции курса: различие «состояние в памяти» и «показанный текст» — обычная инженерная задача, и навык «после изменения явно обновить отображение» важнее, чем новая синтаксическая конструкция. Различение «наблюдения», «проверки контракта» и «формального доказательства» соответствует подходу курса (см. [CURRICULUM-DESIGN.md](CURRICULUM-DESIGN.md), раздел D.1a). Идемпотентность вводится здесь как **наблюдаемое свойство** конкретной операции, а не как формальная спецификация.
